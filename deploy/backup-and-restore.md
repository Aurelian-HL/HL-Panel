# HL-Panel 迁移备份与恢复

从 v0.1.54 起，历史审计日志保存在独立的 PostgreSQL 日志表中，节点心跳不再重复编码全部历史。首次升级会在同一个数据库事务中转换已有日志，不删除历史记录。面板导出、导入和导入前恢复包仍包含全部审计记录，原有备份大小限制继续适用。

**回退到 v0.1.53 或更早版本时，必须同时恢复升级前的完整数据库备份和旧程序。** 新数据库快照格式为 18，旧程序会拒绝读取，避免遗漏独立日志。仅切换程序版本不足以回滚。标准保数据更新会生成数据库备份和 `rollback.sh`；回滚前另行保护升级后的新增业务数据。

从 v0.1.49 起，在 **首页 → HL-Panel 运行状态 → 迁移备份** 中导出备份，或将备份导入另一台已安装的面板。无需手动复制数据库，也不用重新创建规则、节点和订阅。

## 面板内自动迁移

从 v0.1.50 起，在 **迁移备份 → 自动迁移** 中完成新机安装、最终备份传输和恢复。旧机 SSH 凭据不需要提供；新机支持 root 密码或带口令的 SSH 私钥。

### 准备新机

目标必须是全新的 Debian/Ubuntu amd64 公网 IPv4 服务器，能够从当前面板通过 SSH 连接，并能够下载 GitHub 正式安装包。目标已有 HL-Panel 实例或另一迁移任务时会拒绝覆盖。当前面板须为标准安装的正式版本，绑定可申请证书的 HTTPS 域名。本功能保留原域名，IP 访问和换域名使用下方手动导入导出流程。

1. 输入新机 IP、SSH 端口和当前管理员密码，点击 **获取 SSH 指纹**。
2. 通过新机控制台执行 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256`，与页面指纹核对。如果 SSH 服务选用了其他主机密钥，核对对应公钥文件。仅在确认一致后勾选指纹确认。
3. 填写 root SSH 密码或私钥，设置与管理员密码不同的 10～256 字符备份密码，并再次确认。请安全保管备份密码。
4. 勾选全新服务器确认，点击 **准备新服务器**。准备阶段不冻结旧机。新机安装同版本程序，但首次启动即隔离业务接口和后台处理；不会先对外开放后再覆盖数据。
5. 看到 **等待正式切换** 后，打开页面中的 **旧机迁移入口** 并保留标签页。它使用旧机 IP HTTPS 地址的 `/migration`，DNS 切换后仍能操作旧机。IP 入口默认 8443，防火墙需允许访问；核对 IP 入口证书身份。

### 正式切换与证书

输入当前管理员密码并确认 **正式切换** 后，系统等待旧机在途请求完成，暂停业务接口和后台写入，生成最终加密备份，再传输和恢复。恢复包含上文列出的业务数据与流量账本，核对规则、节点等数量及恢复记录。原节点继续使用原身份和原域名，不需要新令牌注册；短暂停止探针上报不会删除节点已经应用的规则。

页面显示 **等待域名解析** 时，将原域名 A 记录改为新机 IP，并移除未使用的 AAAA 记录。所有解析必须指向新机，使用 DNS 直连模式，确保新机 80/443 可从公网访问。系统不会自动修改 DNS。

解析就绪后自动运行域名证书工具，使用 HTTP-01 申请证书。系统直接连接新机 IP，同时校验原域名证书和健康接口；验证通过后才解除新机隔离并重启。看到 **迁移完成** 后，使用原域名和原管理员账号密码登录。必须继续核对节点上线、订阅、规则和真实转发，不能仅凭页面成功就删除旧机。

若证书申请失败，检查域名解析、DNS 代理、80/443、防火墙和证书签发限额。在旧机 `/migration` 重新输入本次任务的 SSH 凭据和原备份密码，点击 **重新连接并继续**。最终备份可在旧机页面下载；两端数据和恢复包均保留，不自动清理。

### 中断续接与撤销

SSH 密码、私钥及备份密码不会写入任务文件、返回状态接口或审计日志，只在进程内存中保留至任务结束或最长 90 分钟。页面刷新不取消正在运行的任务；面板进程重启或超时后，请在旧机迁移入口重新输入凭据。相同任务根据最终备份摘要和数据库恢复记录续接，已提交的导入不会因响应中断而重复覆盖。

新机未启用且任务不在执行时，可先把域名解析指回旧机，再展开 **撤销未完成的迁移**，提供管理员密码和必要的新机 SSH 凭据。系统确认停止新机后才恢复旧机；停止失败则保持旧机隔离。撤销保留两端数据，不会卸载或删除新机。新机启用后禁止直接撤销，需先保护切换后的新写入，再安排备份恢复。

自动迁移不支持合并两个面板、切换域名、迁移节点机器、复制操作系统或自定义 Nginx/systemd 配置。外部集成需另行配置。完成后请按本文“验证业务”逐项核对。

## 备份包含什么

- 管理员、用户、用户组、授权、密码哈希和限额。
- 转发规则、规则组、入口与出口设备组、成员、网络配置、端点池、部署配置与记录。
- 节点身份凭据、配置世代、VLESS / Reality 运行密钥、网关认证密钥。
- 订阅及其固定令牌、站点设置、公告、审计记录、流量账本和采集游标。
- 面板最近 2000 条应用日志及客户密码指纹密钥。

导出文件扩展名为 `.hlbackup`，内部压缩后整体使用 AES-GCM 加密。它不能当普通 ZIP 打开。**文件与备份密码缺一不可；忘记密码无法恢复。** 文件上传上限 64 MB，解压总量上限 128 MB，业务快照上限 16 MB。超限会明确拒绝，不会导出残缺数据。

这不是整机镜像：操作系统、SSH、数据库连接、服务端口、Nginx / systemd 的自定义配置、HTTPS 证书，以及可选外部集成的环境配置和凭据不包含在内。新机器通过安装器配置自己的运行环境；外部集成需要另行设置。旧浏览器登录会话、心跳、探针健康缓存及未完成的节点控制命令不恢复，节点重新上报后更新状态。

## 第一步：在旧面板导出

1. 用管理员账号登录，打开首页的 **迁移备份 → 导出备份**。
2. 填写当前管理员密码。
3. 设置 10～256 个字符的备份密码，再输入一次确认。
4. 点击 **导出加密备份**，等待浏览器下载 `HL-Panel-日期.hlbackup`。
5. 安全保管文件和密码。备份包含节点和规则的访问秘密，不要提交到 GitHub 或发送到公共群聊。

导出包含备份时点的数据。准备正式切换时，暂停后台修改，再导出最终备份；导出后的新增规则、用户和流量不包含在文件中。

## 第二步：安装新面板

在新 VPS 的 root 终端执行：

```sh
curl -fsSL https://raw.githubusercontent.com/Aurelian-HL/HL-Panel/main/install.sh | bash
```

按提示填写新面板域名、管理员账号和密码；无域名可使用安装结果中的 IP HTTPS 入口。默认 `admin / 123456` 首次登录必须改密。新面板版本必须不低于备份版本，低版本会拒绝导入。

新面板沿用自己的数据库连接、端口和服务配置。域名证书由新机器安装器按 DNS 和 HTTP-01 验证条件申请，**备份不会复制旧机器证书或修改 DNS**。同域名正式切换前，可先通过新机 IP 入口导入；解析切换完成后，按 [README 的证书处理步骤](../README.md#证书会自动申请吗) 为新机启用域名证书。自签证书需要配置可信 CA，不要关闭节点 TLS 校验。

## 第三步：在新面板导入

1. 登录新面板，打开 **迁移备份 → 导入恢复**。
2. 选择旧面板导出的 `.hlbackup` 文件。
3. 输入当前新面板的管理员密码，以及导出时设置的备份密码。
4. 点击 **校验并预览**。核对原面板地址、版本、备份时间和规则、节点、用户、订阅等数量。这一步不修改业务数据。
5. 勾选覆盖确认，再点击 **确认导入并恢复**。导入会替换新面板当前业务数据，不能合并两台面板的数据。
6. 系统先创建新面板导入前的加密恢复包，再在同一数据库事务内恢复业务快照和流量账本。失败则保留原业务数据；成功后自动重新载入。
7. 看到 **导入成功** 后等待数秒，点击 **重新登录**，使用 **旧面板备份中的管理员账号和密码**。旧登录会话会失效，这是正常行为。

导入前恢复包使用本次备份密码加密。重新登录后，在同一个浏览器标签页打开 **迁移备份**，可点击 **下载恢复备份**。关闭标签页后，该入口记录可能消失；服务端文件仍保存在面板受管私有备份目录，标准安装为 `/var/lib/hl-panel/migration-backups/`。文件名是导入响应给出的恢复编号，权限为 0600，目录为 0700。不要放宽目录权限或公开这些文件。

网络中断不一定代表事务失败：先重新登录核对管理员、规则数量和节点，再决定是否重试，不要反复覆盖。

## 第四步：让节点连接新面板

### 保持相同域名

停止旧面板接收节点数据，将原域名解析切到新机，并确保新机证书可信。节点继续使用原地址和身份，无需重新注册。不要让两台面板同时接收相同节点的流量上报或配置修改。

### 更换域名或 IP

先导入备份，再在 **每台节点的 root 终端** 执行地址切换工具。将 `https://panel.example.com` 换成新面板地址；IP 入口必须包含实际 HTTPS 端口：

```sh
script=$(mktemp)
if curl -fsSL https://raw.githubusercontent.com/Aurelian-HL/HL-Panel/v0.1.49/deploy/node-control-url.py -o "$script"; then
  python3 "$script" --panel-url https://panel.example.com
  result=$?
else
  result=1
fi
rm -f "$script"
(exit "$result")
```

使用自签证书时，先将新面板 CA 安全复制到节点，再在 `python3` 命令末尾加 `--ca-file /absolute/path/new-panel-ca.pem`。工具只支持标准一键安装的受管节点目录。

工具先通过新面板校验现有节点凭据，再私有备份连接配置、切换地址和 CA、重启 HL Agent。节点身份、规则配置和流量游标保留，**不使用新令牌重新注册**。连接或身份校验失败时不修改配置；切换失败则恢复旧配置。若旧服务也重启失败，会明确提示手动检查，不会把失败当作迁移成功。

面板备份无法主动通知一台仍连接旧地址的远程机器发现新地址，这一步需要在每台节点执行。

## 第五步：验证业务

- 节点重新在线，探针采样正常，期望世代与应用世代一致，最新应用结果成功。
- 规则的入口、出口、目标、限额及分组与旧面板一致。
- 从真实客户端测试转发，不要只用“在线”判断线路可用。
- 打开订阅并测试导入与连接。同域名且入口端口不变时原订阅地址继续有效；更换域名时需分发新域名的订阅地址，令牌保持不变。
- 更换面板机器不会更换节点 IP。节点未迁移且 IP 未变时，原规则入口/出口地址继续保留。

## 回滚

保留旧面板机器和导入前恢复包。需要撤销导入时，使用同一备份密码将 **导入前恢复备份** 按上述流程导回新面板；仍会先备份当前状态，并使浏览器会话失效。恢复将替换当前业务数据，恢复点之后的写入需要另行核对。

需要切回旧面板时，先停止新面板写入，再恢复旧域名解析或逐台把节点地址切回旧面板。旧面板地址切换也会校验原有身份，保留节点配置。切换完成后重新验证心跳、配置和实际转发。

**保留数据更新的回滚**会恢复升级前的程序、受管部署配置和数据库，不能代替任意导入的恢复包。它会覆盖升级后的新写入，执行前请另行备份当前业务数据。

## 迁移后登录或探针异常

- 导入成功时旧浏览器会话会失效一次，请使用备份中的管理员账号重新登录。反复导入会再次撤销会话，不能用重复导入处理登录掉线。
- 持续几分钟掉线时，检查域名的 A、AAAA 记录和代理上游是否全部指向新面板；旧面板必须停止写入。两台机器交替响应会造成新会话在另一台机器上无效。
- 新版本按面板返回的服务器时间判断采样，不再因电脑时间偏差把正常心跳显示为采样过期。面板和节点仍需保持系统时间同步，以免证书验证或服务端租约异常。
- 如设备组出现服务异常，先保留数据更新到最新版本，再检查 `journalctl -u hl-panel-control-api -n 100 --no-pager` 和 PostgreSQL 服务。数据库暂时不可用不会清除浏览器登录。
- 节点未恢复心跳时，核对面板域名、HTTPS 证书及节点连接地址，再检查 `journalctl -u hl-panel-edge-agent -n 100 --no-pager`。更换域名或 IP 时按上文执行地址切换工具；不要通过重新创建令牌覆盖已有节点身份。
