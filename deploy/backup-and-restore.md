# HL-Panel 迁移备份与恢复

从 v0.1.47 起，在 **首页 → HL-Panel 运行状态 → 迁移备份** 中导出备份，或将备份导入另一台已安装的面板。无需手动复制数据库，也不用重新创建规则、节点和订阅。

## 备份包含什么

- 管理员、用户、用户组、授权、密码哈希和限额。
- 转发规则、规则组、入口与出口设备组、成员、网络配置、端点池、部署配置与记录。
- 节点身份凭据、配置世代、VLESS / Reality 运行密钥、网关认证密钥。
- 订阅及其固定令牌、站点设置、公告、审计记录、流量账本和采集游标。
- 面板最近 2000 条应用日志及客户密码指纹密钥。

导出文件扩展名为 `.hlbackup`，内部压缩后整体使用 AES-GCM 加密。它不能当普通 ZIP 打开。**文件与备份密码缺一不可；忘记密码无法恢复。** 文件上传上限 64 MB，解压总量上限 128 MB，业务快照上限 16 MB。超限会明确拒绝，不会导出残缺数据。

这不是整机镜像：操作系统、SSH、数据库连接、服务端口、Nginx / systemd 的自定义配置、HTTPS 证书，以及可选外部集成的环境配置和凭据不包含在内。新机器通过安装器配置自己的运行环境；外部集成需要另行设置。旧浏览器登录会话、心跳、探针健康缓存及未完成的节点控制命令不恢复，节点重新上报后更新状态。

## 第一步：在旧面板导出

1. 用管理员账号登录，打开首页的 **迁移备份 → 导出备份**。
2. 填写当前管理员密码。
3. 设置 10～256 个字符的备份密码，再输入一次确认。
4. 点击 **导出加密备份**，等待浏览器下载 `HL-Panel-日期.hlbackup`。
5. 安全保管文件和密码。备份包含节点和规则的访问秘密，不要提交到 GitHub 或发送到公共群聊。

导出包含备份时点的数据。准备正式切换时，暂停后台修改，再导出最终备份；导出后的新增规则、用户和流量不包含在文件中。

## 第二步：安装新面板

在新 VPS 的 root 终端执行：

```sh
curl -fsSL https://raw.githubusercontent.com/Aurelian-HL/HL-Panel/main/install.sh | bash
```

按提示填写新面板域名、管理员账号和密码；无域名可使用安装结果中的 IP HTTPS 入口。默认 `admin / 123456` 首次登录必须改密。新面板版本必须不低于备份版本，低版本会拒绝导入。

新面板沿用自己的数据库连接、端口和服务配置。域名证书由新机器安装器按 DNS 和 HTTP-01 验证条件申请，**备份不会复制旧机器证书或修改 DNS**。同域名正式切换前，可先通过新机 IP 入口导入；解析切换完成后，按 [README 的证书处理步骤](../README.md#证书会自动申请吗) 为新机启用域名证书。自签证书需要配置可信 CA，不要关闭节点 TLS 校验。

## 第三步：在新面板导入

1. 登录新面板，打开 **迁移备份 → 导入恢复**。
2. 选择旧面板导出的 `.hlbackup` 文件。
3. 输入当前新面板的管理员密码，以及导出时设置的备份密码。
4. 点击 **校验并预览**。核对原面板地址、版本、备份时间和规则、节点、用户、订阅等数量。这一步不修改业务数据。
5. 勾选覆盖确认，再点击 **确认导入并恢复**。导入会替换新面板当前业务数据，不能合并两台面板的数据。
6. 系统先创建新面板导入前的加密恢复包，再在同一数据库事务内恢复业务快照和流量账本。失败则保留原业务数据；成功后自动重新载入。
7. 看到 **导入成功** 后等待数秒，点击 **重新登录**，使用 **旧面板备份中的管理员账号和密码**。旧登录会话会失效，这是正常行为。

导入前恢复包使用本次备份密码加密。重新登录后，在同一个浏览器标签页打开 **迁移备份**，可点击 **下载恢复备份**。关闭标签页后，该入口记录可能消失；服务端文件仍保存在面板受管私有备份目录，标准安装为 `/var/lib/hl-panel/migration-backups/`。文件名是导入响应给出的恢复编号，权限为 0600，目录为 0700。不要放宽目录权限或公开这些文件。

网络中断不一定代表事务失败：先重新登录核对管理员、规则数量和节点，再决定是否重试，不要反复覆盖。

## 第四步：让节点连接新面板

### 保持相同域名

停止旧面板接收节点数据，将原域名解析切到新机，并确保新机证书可信。节点继续使用原地址和身份，无需重新注册。不要让两台面板同时接收相同节点的流量上报或配置修改。

### 更换域名或 IP

先导入备份，再在 **每台节点的 root 终端** 执行地址切换工具。将 `https://panel.example.com` 换成新面板地址；IP 入口必须包含实际 HTTPS 端口：

```sh
script=$(mktemp)
if curl -fsSL https://raw.githubusercontent.com/Aurelian-HL/HL-Panel/v0.1.47/deploy/node-control-url.py -o "$script"; then
  python3 "$script" --panel-url https://panel.example.com
  result=$?
else
  result=1
fi
rm -f "$script"
(exit "$result")
```

使用自签证书时，先将新面板 CA 安全复制到节点，再在 `python3` 命令末尾加 `--ca-file /absolute/path/new-panel-ca.pem`。工具只支持标准一键安装的受管节点目录。

工具先通过新面板校验现有节点凭据，再私有备份连接配置、切换地址和 CA、重启 HL Agent。节点身份、规则配置和流量游标保留，**不使用新令牌重新注册**。连接或身份校验失败时不修改配置；切换失败则恢复旧配置。若旧服务也重启失败，会明确提示手动检查，不会把失败当作迁移成功。

面板备份无法主动通知一台仍连接旧地址的远程机器发现新地址，这一步需要在每台节点执行。

## 第五步：验证业务

- 节点重新在线，探针采样正常，期望世代与应用世代一致，最新应用结果成功。
- 规则的入口、出口、目标、限额及分组与旧面板一致。
- 从真实客户端测试转发，不要只用“在线”判断线路可用。
- 打开订阅并测试导入与连接。同域名且入口端口不变时原订阅地址继续有效；更换域名时需分发新域名的订阅地址，令牌保持不变。
- 更换面板机器不会更换节点 IP。节点未迁移且 IP 未变时，原规则入口/出口地址继续保留。

## 回滚

保留旧面板机器和导入前恢复包。需要撤销导入时，使用同一备份密码将 **导入前恢复备份** 按上述流程导回新面板；仍会先备份当前状态，并使浏览器会话失效。恢复将替换当前业务数据，恢复点之后的写入需要另行核对。

需要切回旧面板时，先停止新面板写入，再恢复旧域名解析或逐台把节点地址切回旧面板。旧面板地址切换也会校验原有身份，保留节点配置。切换完成后重新验证心跳、配置和实际转发。

**保留数据更新的回滚**会恢复升级前的程序、受管部署配置和数据库，不能代替任意导入的恢复包。它会覆盖升级后的新写入，执行前请另行备份当前业务数据。
