# 面板域名授权 v2

本指南描述当前本地候选实现。本轮没有发布正式版本，也没有升级生产；Linux 全新安装、systemd 升级及回滚仍须在隔离虚拟机运行，脚本语法检查不能代替这些验收。

## 授权规则

HT 由超级管理员发放月、季、半年、年、自定义天数、指定到期日或永久授权。一个码绑定一个管理域名和一个面板实例。月、季、半年、年按北京时间自然月计算并夹取月末，相对期限从首次成功激活起算；续期从当前时间与原到期时间中的较晚值起算。永久授权仍需要定期同步签名状态。

安装时须填写不含协议、路径或端口的管理域名，并验证 `_hl-license.管理域名` 的 DNS TXT。IP 不能代替授权域名。网站 A 记录可以稍后指向主机；TXT 用于证明域名控制权，不会修改网站解析。安装器不会替用户修改 DNS。

节点继续使用面板发放的一次性节点令牌，不要求另买面板授权。面板授权到期、被撤销或离线租约失效后，禁止新增、修改和删除管理资源；已保存的规则、订阅、节点心跳与存量运行接口继续执行原有认证和权限校验，不因授权状态主动清空。登录、密码恢复所需操作及授权同步入口保留。已有流量限额、账号停用等业务规则仍然有效。

概览和系统设置显示绑定域名、商业到期日、同步状态。到期前 3 天每日提醒，可选择“立即支持”或“今日不再提醒”；提醒按管理员与北京时间日期分别保存。HT 续期后可等待自动同步，或点击“立即同步”。续期只改变授权，不改客户 UUID、订阅 Token、URL 或规则。

## 发布方信任配置

独立签发服务配置见源码中的 `apps/panel-license-issuer/README.md`。签发服务使用独立数据库；HT 后端独占管理 token，并从当前超级管理员会话生成审计操作者，浏览器不能自报 actor。私钥、管理 token、数据库 DSN 只存受限秘密文件，不进入仓库、浏览器或发行包。

GitHub 正式发行需配置三个公开 repository vars：

| 名称 | 内容 |
| --- | --- |
| `HL_PANEL_LICENSE_ISSUER_URL` | 签发服务 HTTPS origin，不含路径、查询或账号 |
| `HL_PANEL_LICENSE_ISSUER_ID` | 稳定 HTTPS issuer 标识，与签发服务一致 |
| `HL_PANEL_LICENSE_PUBLIC_KEYS_B64` | 公钥对象 JSON 的无 padding base64url 编码；对象为 key ID → 32 字节 Ed25519 公钥的无 padding base64url |

PowerShell 构建使用 `LicenseIssuerURL`、`LicenseIssuerID`、`LicensePublicKeys` 参数，最后一项传原始公钥对象 JSON。两条构建路径共用信任校验器；缺配置、格式不合法或包含 `disposable-ci-only` 测试身份时拒绝正式构建。正式 `control-api` 将信任钉入编译产物，运行时环境变量不能更换签发方或关闭校验。轮换签发公钥需先以新发行包分发兼容公钥，再切换签发 key ID，保留旧公钥直到旧缓存完成更新。

CI 的临时签名候选与正式候选是两个不同 artifact。临时私钥只用于隔离验收，禁止发布临时候选或将测试私钥打进正式包。

## 新安装

取得 HT 授权码、确认能维护该域名 TXT 后，使用正式同标签的安装入口，并填写 `--domain panel.example.com`。安装器在终端隐藏读取授权码；不要将授权码写入 `--license-code` 或命令历史。

需要预置时，可从标准输入创建 root 独占文件，不在命令中写明码：

```sh
sudo install -m 600 /dev/null /root/hl-license-code
read -r -s -p 'HT 授权码：' hl_install_code
printf '\n'
printf '%s' "$hl_install_code" | sudo tee /root/hl-license-code >/dev/null
unset hl_install_code
```

随后在安装命令中添加 `--license-code-file /root/hl-license-code`。授权码文件必须是 root 持有的普通文件，权限 600 或更严格。文件模式只替代隐藏输入，DNS 验证步骤仍需交互终端。

安装器会展示 TXT 记录名、值和证明过期时间。到 DNS 服务商添加记录，等待传播后回车验证。证明有效 10 分钟；过期后重跑命令获取新证明。失败不会永久占用码；成功绑定后的本机身份必须保留。安装后请按自身秘密管理流程清理输入码文件。

## 旧面板首次接入

不要运行全新安装器覆盖旧实例，也不要直接用旧升级器跨过首次授权准备。

1. 备份当前程序、数据库及配置，下载候选正式包和摘要；校验归档 SHA256、包内完整 `SHA256SUMS` 及来源，提取到一个新的受限目录。
2. 在该目录执行 `sudo bash deploy/setup-panel-license.sh --domain panel.example.com`。默认使用同包 `bin/control-api`，完成隐藏授权码输入和 DNS TXT 验证。可添加上述 `--license-code-file`。
3. 该步骤保存独立授权身份和受管 systemd 写目录配置，执行 daemon-reload；不改旧环境文件、不重启服务、不修改客户账号、规则或订阅。受管 drop-in 只保留一个 `.previous`。
4. 随后使用系统更新安装该正式版本。新版升级器会在备份、停止服务前用候选程序验证本机签名授权；已签名的到期或撤销绑定仍允许安全升级，不会自动恢复管理权限。
5. 验收登录、授权日期、同一订阅地址、规则和节点心跳。若当前程序已经是授权版而接入身份前未读取身份，需要受控重启面板控制服务；不要重启数据平面引擎来刷新授权。

没有域名的旧 IP 面板需先选定并绑定可验证的管理域名。网页域名、Nginx、TLS 与授权域名应由运维在备份后分别核对；此脚本不会擅自改站点配置。正式启用域名证书按同包 `README.md` 操作。

## 状态目录与回滚

授权身份独立存放在 `/var/lib/hl-panel-license`：

| 文件 | 用途 |
| --- | --- |
| `instance-id` | 安装器生成的稳定实例编号 |
| `instance-key` | 本实例 Ed25519 私钥，属于秘密 |
| `identity.json` | 管理域名与实例编号 sidecar |
| `state.json` | 签名声明、待验证证明与提醒状态 |

目录及文件仅开放给需要使用它的 root/hlpanel，安装与接入脚本拒绝符号链接、硬链接或未知文件。运行时每次加载重新验签，不能直接编辑 JSON 变更授权。不要删除该目录“重新注册”，也不要将身份克隆到另一个面板。独立加密备份并限制读取权限；常规客户数据库备份不替代该身份备份。

授权身份在安装失败、程序更新或代码回滚时继续保留。代码回滚不得覆盖授权身份、HT 授权数据库或客户数据库；若数据库结构升级需要恢复历史备份，应按主更新器的回滚说明单独处理，并先保存升级后的新增数据。授权身份不可随程序降版回退到旧签名缓存。

迁移或更换域名必须由 HT 超级管理员显式换绑并审计，保留原商业到期、递增 revision，旧实例随后无法同步，新实例重新完成 DNS 证明。旧缓存可能在剩余签名租约内继续有效，不能承诺撤销或换绑立刻使离线旧实例失效。撤销不能通过普通续期、换码或换绑恢复。

## 同步与故障边界

正常约每 30 分钟同步，暂时失败采用有界退避；有效缓存保留。离线租约最长 24 小时，有期授权的 active 租约不越过商业到期；刷新时间夹取在签发时间与租约到期之间。网络故障不会延长商业到期。超过租约仍保留存量转发，但限制管理，恢复有效签名后解除。

签名损坏、身份不匹配、revision 或时间回退均不会被当作有效新状态。缺配置的授权版以受限管理状态启动并保护存量服务；应恢复身份或按流程接入，不应删除客户数据或关闭 TLS 校验。需要手动核对时可执行：

```sh
sudo -u hlpanel /opt/hl-panel/current/bin/control-api license status \
  --state-dir /var/lib/hl-panel-license
```

授权保护针对正常发行包和管理流程。拥有主机 root 或源码的人可以修改程序，不能承诺仅靠域名码绝对防止分享或破解。项目仅供合法个人用途；面板会在本机保存账号、规则和统计，授权服务接收必要授权与审计信息，不能宣称“不记录任何用户数据”。
