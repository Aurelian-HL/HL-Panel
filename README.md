**HL-Panel 是专线与 VPS 的转发管理面板。** 在一个控制台管理转发规则、入口 / 出口设备组、节点、订阅和流量。支持 TCP / UDP、VLESS Reality、SOCKS5 落地与组间隧道；通过已配置的统一入口，可让多台后端分担新连接，并在故障检测后由其余健康节点继续承接。

**实际效果取决于部署方式。** 组内规则同步、统一入口负载和入口高可用分别解决不同问题，下面说明各自能力、配置前提和故障边界。

本仓库公开安装与更新脚本、正式二进制发行包。应用源码、开发历史与构建记录在独立私有仓库维护；GitHub 的 **Source code** 压缩包仅含公开交付文件，安装请使用 Release 中的 `hl-panel-linux-amd64.tar.gz`。服务器安装与更新无需源码仓库凭据。

## 功能一览

| 模块 | 已实现内容 |
| --- | --- |
| 转发规则 | 创建、编辑、暂停、恢复、删除、规则分组、搜索筛选、自动分配端口、配置下发及节点应用回执 |
| 批量开通 | 每行“昵称 + SK5”，昵称留空使用上游 IP；一批最多 500 条，支持批量暂停、恢复、分组和删除 |
| 协议与落地 | TCP / UDP 转发、VLESS Reality + Vision TCP 入口；VLESS 可选择直连或 SOCKS5 落地，组间支持隧道转发 |
| 设备组 | 入口组、出口组、成员管理、权重与优先级、注册入组、重装换组、退役及节点清理 |
| Reality 配置 | 创建时检测候选 Target / SNI；支持重新检测和手动修改，订阅按已保存的规则配置生成 |
| 订阅管理 | 单规则订阅、多线路订阅、TXT / YAML、ZIP 导入包、在线订阅与节点二维码 |
| 子账号与用户组 | 子账号共用面板登录入口；管理员可设置设备组权限、规则数量、速率、总用量及到期提醒，支持删除 |
| 流量计量 | 按整数 bytes 累计客户、规则与设备组用量，保留 UTC 月汇总；支持规则额度及按月重置 |
| 设备探针 | CPU、内存、磁盘、网络速率、连接与流量采样；设备备注仅保存在当前浏览器，可替代 IP 显示 |
| 节点维护 | 一条命令安装，自动检查并补齐依赖；面板发起正式版更新、同版本修复，查看持久化任务进度 |
| 授权 | 免费额度、外部商城购买入口、一次性兑换码激活、授权状态同步及未确认兑换结果恢复 |
| 系统管理 | 个人中心、管理员密码修改、系统设置、操作日志、正式版本检查与面板保数据更新 |

**用户管理中的用户是可以登录面板的子账号。** 转发规则及订阅客户与子账号分开管理，新增规则不要求创建一个面板登录账号。

客户与规则的到期时间用于提醒，不因到期停止转发或订阅；这与下文的面板软件授权状态是两回事。

HL 负责线路、规则、节点和转发。外部运营后台可通过接口管理规则与订阅；客户联系方式、金额、订单等运营资料不属于转发配置。

## 专线透明转发与多机协同

**你已有专线或互通的内网，HL 负责把入口、出口和转发规则组织起来。** 典型部署如下：

```text
客户端 → 统一入口 → 已有专线 / 组间隧道 → 出口 A / B / C → 目标服务或 SK5
```

| 你关心的场景 | 当前能做到什么 | 配置前提与边界 |
| --- | --- | --- |
| 专线透明转发 | TCP 网关透传原始数据，应用 TLS、VLESS / Reality 等协议由后端处理 | 不解密原始应用 TLS；专线或内网需事先互通，HL 不代替运营商开通专线 |
| 多台一起承担连接 | 已实现的统一入口 TCP 网关按权重轮询、最少连接或稳定哈希，为每条新连接选择一台健康后端 | 需要部署并配置统一入口网关；只把机器加入设备组，不会自动把所有客户连接均匀分给每台 |
| 一台故障，其余继续 | 网关健康检测确认后避开故障后端，把后续新连接交给其他健康节点；恢复后可重新加入选择 | 故障检测有时间窗口；已连到故障机的旧连接需要客户端重连，不能无缝搬到另一台 |
| 组间隧道使用多个出口 | 已实现的 QUIC / KCP 隧道编译路径支持多个出口轮询及失败避让 | 隧道出口选择与上面的 TCP 网关是不同路径，不能把网关的全部调度策略视为隧道默认能力 |
| 统一入口本身故障 | 可结合多个入口及外部健康检测、DNS / GTM 等部署入口高可用 | 单个入口仍是单点；HL 不会自动修改第三方 DNS，单纯添加多条 A / AAAA 记录不等于故障自动摘除 |
| 多机带宽 | 多条连接可以分散到不同机器，分担整体负载 | 单条连接固定使用一个后端，不会把多台机器的带宽相加给同一条连接 |

**已验证的范围：** 隔离 TCP 测试覆盖 10 台后端轮询、停掉其中 1 台后由其余 9 台接新连接、恢复后重新加入。该结果不代替具体专线的公网验收；UDP、QUIC / KCP 及真实客户端需要按实际部署分别验证，不能据此宣称全部生产链路已经验收。

## 项目组成

| 角色 | 主要组件 | 作用 |
| --- | --- | --- |
| 面板服务器 | Go 控制 API、Vue 3 管理端、PostgreSQL、Nginx | 保存配置、管理账号与规则、提供订阅及节点控制接口 |
| 节点服务器 | HL Agent、主机探针、Xray / GOST | 接收并应用规则，承担实际转发、采样和流量上报 |

设备组用于统一编排成员和规则。使用统一业务域名或稳定入口时，可向客户提供一个服务地址。**DNS 多 A 记录与面板内的新连接调度是不同机制**：客户端直接解析到节点时，地址选择取决于 DNS 和客户端，HL 不会自动修改第三方 DNS / GTM。

面板保存成功、节点心跳在线和客户端转发成功是三个不同状态。请同时检查配置应用回执，并用实际客户端传输数据。

## 快速开始

顺序：**安装面板 → 登录改密 → 创建设备组 → 安装节点 → 创建规则 → 验证订阅与转发**。

### 安装要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Debian 12 / Ubuntu 22.04 及更新版本的 apt + systemd 环境 |
| 架构 | Linux x86_64 / amd64；当前正式包不提供 ARM 安装包 |
| 权限 | 在目标服务器使用 root 执行安装 |
| 面板域名 | 管理域名解析到面板公网 IPv4；自动签证书时使用 DNS 直连，且不保留 AAAA 记录 |
| 面板入站 | TCP 80、443；需要 IP HTTPS 入口时放行 TCP 8443 或自定义端口 |
| 节点入站 | 放行规则实际使用的 TCP / UDP 业务端口；SSH 端口不等于业务端口 |
| 出站访问 | GitHub 下载服务、面板 HTTPS；面板授权操作还需访问配置的授权服务 |

云安全组与系统防火墙需自行放行。节点依赖自动补齐当前使用 Debian / Ubuntu 的 apt 流程；不等于任意 Linux 发行版均可直接安装。

### 1. 安装面板

仅在**全新面板服务器**执行：

```bash
curl -fsSL https://raw.githubusercontent.com/Aurelian-HL/HL-Panel/main/install.sh | bash
```

缺少 `curl` 时先执行：

```bash
apt-get update && apt-get install -y curl ca-certificates
```

按提示填写管理域名、管理员账号与密码。安装器下载同一正式标签的安装脚本和程序包，校验摘要，安装依赖、数据库与服务，并尝试签发域名 HTTPS 证书。

- 管理域名填写**你自己的面板域名**，不带协议、端口或路径。`panel.example.com` **仅为格式示例，请替换为自己的域名，不要原样填写**。
- 默认管理员为 `admin`；密码留空使用 `123456`，首次登录强制改密。建议安装时直接设置自己的密码。
- 安装完成后打开终端显示的 HTTPS 地址。已有面板使用更新命令，不用全新安装覆盖。

### 2. 安装节点并入组

1. 在面板创建设备组，确定它是入口还是出口。
2. 打开目标组的 **对接 → 自动探测线路**，生成一次性注册令牌。
3. 复制面板生成的**完整命令**，到该节点服务器的 root 终端执行。
4. 等待注册成功，回面板核对组成员、Agent 版本与探针采样。

完整命令已经包含面板地址和令牌，会安装 HL Agent、探针、Xray / GOST 及节点更新服务。已满足的依赖跳过，缺少的按需补齐，包括 Python、CA、网络与 TC 工具；BBR2 / BBR 按现有内核能力尝试启用，不为此更换内核。

默认令牌有效期 15 分钟，也可选择 30 分钟或 1 小时；每台机器单独生成。不要只复制令牌或运行缺少参数的 `install-node.sh`。

新装节点默认获取最新正式版；已有节点的默认更新命令跟随所属面板正式版，两者用途不同。重装或换组使用目标组的新命令，会保留节点身份和累计用量，但切换可能短暂中断该节点连接。

### 3. 创建规则并使用

常见流程：**转发规则 → 创建 → 选择入口组 → 填昵称与完整 SK5 → 保存 → 等待节点应用 → 获取订阅或二维码**。

批量创建每行一条，例如以下仅用于说明格式的地址：

```text
客户甲 192.0.2.10:1080:example-user:example-password
192.0.2.11:1080:example-user:example-password
```

第二行昵称留空，将使用 `192.0.2.11`。批量入口使用 VLESS + Reality、SOCKS5 出站并自动分配端口；其他协议按单条创建流程配置。

保存后核对节点的配置应用状态，再在客户端导入在线订阅、导入包或二维码。直连、SOCKS5 落地、跨组转发需要各自的目标与网络可达；订阅下载成功不等于线路已连通。

## 面板与节点更新

**面板和节点独立更新。** 面板升级不会自动把所有节点一起升级。

| 对象 | 网页入口 | 终端入口与影响 |
| --- | --- | --- |
| 面板 | 首页运行状态中的版本更新 | 在面板机执行 `update.sh`；控制 API、管理页面和订阅下载切换期间短暂不可用 |
| 节点 | 设备探针 / 节点清单中的“更新” | 在目标节点执行 `update-node.sh`；程序切换会中断该节点现有连接 |

已有面板的 root 终端：

```bash
curl -fsSL https://raw.githubusercontent.com/Aurelian-HL/HL-Panel/main/update.sh | bash
```

已有节点的 root 终端：

```bash
curl -fsSL https://raw.githubusercontent.com/Aurelian-HL/HL-Panel/main/update-node.sh | bash
```

面板更新保留账号、规则、设备组、订阅、累计计量和配置；节点保身份更新不需要新令牌，也不重新换组。节点默认读取所属面板的正式版本。旧节点尚未接入网页更新时，先执行弹窗给出的一次接入命令。

面板维护期间，节点保留最后有效转发配置；面板更新器不会因此远程升级节点引擎。节点更新应逐台进行，确认真实转发后再继续，不同时切换整组。

节点安装与更新完成后清理本次临时安装、恢复材料，不创建长期节点安装归档；尚在执行、结果未确认或恢复未完成的任务保留必要材料。面板更新的数据库恢复点与节点临时目录分别管理，以更新器实际输出为准。

发行以 [GitHub Releases](https://github.com/Aurelian-HL/HL-Panel/releases) 为准。修改 README、提交 main 或通过验证构建，不等于已发布新安装包或升级生产。Xray / GOST 使用正式包中固定版本，不单独追踪上游 latest。

## 免费版与授权

- **免费版：整个面板最多 1 个设备组、2 条未删除规则**，暂停规则也计数，不是每用户各有 2 条。
- 全新安装通过 HTTP-01 自动登记管理域名。需要域名解析正确、公网 TCP 80 与验证路径可达；暂未登记成功时按状态提示处理，无需反复重装。
- 侧栏 **购买授权** 打开外部商城；个人中心的 **兑换激活 / 恢复结果** 进入授权页。
- `hlr1_` 一次性兑换码首次成功使用后绑定当前域名与面板实例，自动进行 HTTPS 域名证明，**无需手动添加 TXT**。面板域名 443、可信证书与挑战路径必须可达。
- 兑换结果未确认时使用“恢复兑换结果”，避免重复提交；旧 `hl2_` 授权与新兑换码是不同流程。
- 授权到期限制受保护的管理写入，保留现有转发、订阅、节点心跳及授权恢复入口。支付、订单查询与发货由外部商城负责，HL 不内置支付系统。

外部授权服务的版本、商品配置和可达性决定兑换是否可用；仅升级 HL 不等于外部商城、签发服务已完成部署。

## 流量统计与状态口径

累计流量按**整数 bytes** 保存和累加，展示时再转换为 KB / MB / GB，单位换算采用 1024。重复上报通过持久化序号与回执去重；保留客户、规则、设备组累计与 UTC 月汇总。

当前使用汇总存储，**不永久积攒每次上报的明细**。旧明细由后台按批整理，保留累计值与必要防重状态；不再提供任意分钟、小时、日期区间的原始历史明细查询。数据库可复用空间不代表操作系统文件立即缩小。

连接数与速率来自节点采样；**规则页的在线筛选当前采用 5 分钟快照，并非逐秒实时人数**。当前版本部分统计按规则绑定的客户归属去重，多条规则共用归属时可能被合并；按规则自身状态统计的修复列入 [下一批计划](ROADMAP.md#a1--修正规则在线统计)，尚未发行。探针在线、业务端口可达、代理认证成功和实际访问成功应分别判断。

- 配置下发有期望代次和应用回执；保存、领取、校验、应用需分别确认。节点遇到不可达的控制面或无效新配置时保留最后有效配置。
- 规则与成员变动尽量只应用受影响配置，但**不承诺所有操作、所有协议均零重启或长连接迁移**。节点升级、换组与引擎替换需考虑连接重连。
- UDP 包含原生转发与组间隧道场景，需核对双方版本、能力、业务端口及上游支持；隔离回环验收不等于生产公网全链路验收。
- 面板自带受控节点更新入口，**未提供通用交互式 SSH 终端**。
- 订阅生成读取当前规则配置；外部运营系统的缓存与同步仍取决于双方接口流程，不能把 HL 修改成功等同于第三方订阅立即刷新。
- 安装包提供 SHA-256 与内部文件摘要校验；摘要校验不等于独立发行签名。自有程序采用混淆构建，不能保证不可逆向。

## 常见问题

| 问题 | 检查方向 |
| --- | --- |
| 更新面板后节点版本没变 | 面板与节点独立更新。到设备探针的“更新”查看目标版本与接入状态。 |
| 安装后节点在线，但规则不能用 | 核对业务端口、防火墙、配置应用回执、上游 SK5 认证和真实客户端；心跳只是管理链路正常。 |
| 在线统计一直为 1，或与规则行状态不同 | 当前版本可能按共用客户归属合并；按规则统计的修复待发，不代表只有一个真实用户连接。见 [路线图](ROADMAP.md#a1--修正规则在线统计)。 |
| 部分苹果设备订阅提示 SSL 失败 | 对照同一网络下 Safari 与客户端的结果，记录失败时间；核对实际解析、证书链及 TLS / HTTP 协议。不能仅凭错误提示判定手机时间或运营商问题，也不要关闭证书验证。 |
| 域名证书首次签发失败 | 修好 DNS、80 端口及签发条件后，在面板机执行 `hl-panel-enable-domain-tls`，再验收公网 HTTPS。 |
| IP HTTPS 入口有证书警告 | IP 入口默认使用自签证书，与域名 443 证书不同。节点和客户端应使用受信任的 HTTPS 入口。 |
| 流量明细不再显示 | 当前保留准确累计与 UTC 月汇总，不再永久保留逐次上报明细；这不表示累计计量被清零。 |
| 多 IP 的一部分连不上 | 分别测试每个 IP 的真实业务端口；Ping 或 SSH 22 可达不能证明转发端口可用。第三方 DNS / GTM 的摘除策略需独立配置。 |

## 反馈与使用说明

通过 [Issues](https://github.com/Aurelian-HL/HL-Panel/issues) 提交问题，请附：面板与节点版本、系统与架构、具体操作、失败时间与时区、客户端版本，以及脱敏日志。安装或更新问题请注明命令执行在面板机还是节点机。

**不要公开密码、注册令牌、完整订阅地址、用户 UUID、私钥或数据库连接串。** 公开仓库用于安装交付和问题反馈，完整应用源码不在此仓库发布。

本项目供个人学习与合法授权使用，请遵守所在地法律及上游服务规则。为管理账号、节点与计量，面板会保存必要业务状态；请由部署者自行管理访问权限与数据安全。

感谢 [Xray-core](https://github.com/XTLS/Xray-core) 与 [GOST](https://github.com/go-gost/gost) 等上游项目。随包组件保留各自许可证；版本、来源、摘要及许可证以正式包内清单为准。
