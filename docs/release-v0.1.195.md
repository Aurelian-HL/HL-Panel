# v0.1.195 — 新机节点安装遇到系统更新时自动等待

修复新机复制节点安装命令后，因为系统自动更新占用 apt/dpkg，首次执行退出、再次执行才能安装的问题。

- 面板复制命令、外层下载脚本和正式安装脚本采用同一等待策略，覆盖缺少 curl、CA 证书及节点运行依赖的机器。
- 确认软件包锁被其他进程持有时，每 5 秒重试，累计等待最多 300 秒；锁释放后继续本次安装，无需重复粘贴命令。
- 权限不足、下载失败、包不存在及 dpkg 中断等其他错误立即保留原错误退出，不无限重试。
- 安装可选时间同步包时，软件源刷新失败后不再继续安装；等待信息会显示在终端。

安装命令中的授权信息、现有节点身份、计量和转发配置不变。不会删除系统锁、杀死系统更新进程或清空计量。

## 更新范围

更新面板后重新生成、复制节点安装命令。之前已经复制的旧命令含旧前缀，不会自行变更。
已验收的 v0.1.194 节点不需要为此安装修复再次重启；新增节点使用 v0.1.195。
本版延续 v0.1.194 流量积压隔离与计量保护，Xray/GOST 版本不变。
正式包在本地保护构建，不使用付费 GitHub 构建。

## 验证边界

发布以本版本本地回归与隔离 Linux 验收记录为准；生产面板逐台升级另行记录。
没有执行全部 Debian/Ubuntu 版本的完整安装矩阵，也没有用生产软件包锁做故障注入。
持续占锁超过 5 分钟仍会明确失败，需要先处理机器的系统更新；不是所有安装失败都会自动重试。
