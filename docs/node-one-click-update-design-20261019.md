# 节点一键更新

日期：2026-10-19。本文描述已接入代码的行为；正式可用版本以 GitHub Release 和验收记录为准，提交 main 不等于发布或升级机器。

## 操作流程

1. 先通过系统更新升级面板。
2. 新节点在“节点令牌”复制安装命令，自动安装本机更新服务。
3. 旧节点打开探针或节点清单的“更新”，在该节点 root 终端执行弹窗给出的固定版本保身份命令一次，不要重新注册或换组。
4. 等节点上报更新能力后刷新，选择正式版本并点击更新。同版本可重新安装修复。
5. 关闭页面不取消任务，重开继续查看；只有未领取的任务可取消。提交超时后刷新查询，重试复用原任务标识。

使用现有管理员登录权限，无额外密码步骤。全局同时只执行一个任务。首版支持 Linux amd64；目标版本不低于节点且不高于面板，仅允许官方正式发布版本。

下载期间保留原转发。切换会重启节点 Agent 和引擎，该节点已有连接需重连；身份、设备组、规则、Reality 材料、订阅 URL 和流量账本保留，不能承诺长连接无感升级。

## 实现边界

独立 nodeupdates 领域持久化任务，PostgreSQL 快照保存管理员、幂等标识与私有领取租约。管理员与节点接口身份隔离，节点只领取和回报自身任务。公开状态不返回租约或注册凭据，所有任务变更记录审计。重复领取和重复进度不重写数据库快照。

| 调用方 | 接口 | 用途 |
| --- | --- | --- |
| 管理员 | GET/POST /api/v1/nodes/{node_id}/updates | 状态与创建任务 |
| 管理员 | POST /api/v1/nodes/{node_id}/updates/{task_id}/cancel | 取消未领取任务 |
| Agent | POST /api/v1/agent/update-task/claim | 领取自身任务，重启保持租约 |
| Agent | POST /api/v1/agent/update-task/result | 回报受约束阶段与结果 |

Agent 通过原有 HTTPS 身份主动接入，空闲每 30 秒、活动每 5 秒检查，旧面板 404 退避五分钟。不改变客户在线状态五分钟采样。

独立 root systemd 服务只监听 /run/hl-panel-node-update.sock，root:hl-edge 0660，并核验对端 UID。Agent 不提权，面板不保存 root 密码，不新增公网维护端口，不接受任意命令、URL、路径或脚本。

GitHub Release 必须非草稿、非预发布，资产 URL 固定且含 SHA256 digest。任务绑定固定 tag 及包摘要，节点再次校验正式包和内部清单。SHA256 是完整性校验，不是独立发布者签名。安装更新服务自身文件不会重启正在执行的 worker。

## 验收与恢复

成功必须满足 root 私有安装完成回执与本次待验收临时目录、目标编译版本、新心跳、最新 desired/applied 代数和摘要，以及引擎实际持有对应 TCP/UDP 监听。同版本修复也必须有完成回执，不能仅看版本相同。这些是程序检查；真实代理和订阅仍需客户端验收。

任务和私有日志保存在 `/var/lib/hl-panel-node-update/`，权限 0700。本次程序替换材料位于 `/opt/hl-panel/.node-update-vX.Y.Z-.../`，身份与流量账本留在原位置。验收成功或成功恢复后自动清理临时目录，不创建长期归档或公共 `rollback.sh`。执行中的旧 worker、旧更新器首次衔接时兼容 `/var/backups/hl-panel-node/update-vX.Y.Z-.../`，只清理这次已完成的目录；不会重启正在执行任务的 worker。清理失败保留准确任务结果与目录引用，通过已有状态查询重试，不把成功误报为更新失败。

未领取任务超过 15 分钟由领取检查标记过期。已领取任务不因失联或请求超时重新分配。worker 中断进入“结果待核实”，保持全局锁，不自动重复安装。切换后 180 秒未完成本机验收则尝试回滚，失败继续待核实。

存在合法未完成事务的待核实任务，可在节点 root 终端查看日志，再用固定 socket /rollback 提交仅含实际任务 ID 的 JSON，等待 Agent 补报：

```sh
curl --unix-socket /run/hl-panel-node-update.sock http://localhost/status
curl --unix-socket /run/hl-panel-node-update.sock -H 'Content-Type: application/json' --data '{"id":"实际任务ID"}' http://localhost/rollback
```

缺少恢复材料的异常中断需管理员现场核实，没有强制解除锁入口；不得删状态文件伪造成功或放行。历史任务最多 2000，达到上限拒绝创建，暂无自动清理。

## 验证和发布

测试覆盖权限隔离、幂等、跨重启租约、PostgreSQL 无变化不写入、弹窗错误恢复、root 参数白名单、维护文件恢复，以及隔离 Linux/systemd 的真实升级、重放、worker 中断回滚、身份保留和真实引擎转发。Linux/root/PostgreSQL 测试必须在对应环境实际执行，Windows 编译或跳过不算通过。

正式发布生成新 tag 和新包，不覆盖旧版本。检查通过后先升级面板，旧节点命令接入，再从真实面板发起同版本修复，验收完整任务链路及客户端。提交、版本和真实结果记录在独立验收报告中，不在本文预先宣称完成。
