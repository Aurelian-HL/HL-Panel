## 删组事务如何验收

1. 在隔离数据库的真实 COMMIT 注入延迟错误，并核对错误阶段与 SQLSTATE。
2. 确认失败后完整已提交快照、原配置、审计和运行材料保持；没有提前通知节点应用撤回。
3. 移除故障，使用同一请求重试，确认仅发布一个撤回配置版本。
4. 关闭并重新打开仓库，确认被删组的规则、端点和身份撤销结果持久保存；独立节点不变，共享节点保留其他规则片段。
5. 重放不改变业务快照或唤醒节点；重新入组恢复探针并保留节点身份，独立节点配置不变。

## 保留的失败及验收边界

首次跨包并行启动真实引擎时出现启动失败，单独运行及串行运行通过。怀疑本地监听资源冲突，但没有足够日志确定唯一原因；不以重跑成功掩盖首次失败。

新增数据库组合回归首跑暴露两处测试前提错误：已应用配置不会再由待下发接口返回，幂等写入也可能推进数据库行版本。已改为读取准确配置代次、比较业务快照与通知，再通过验证；没有据此改变产品行为。

Windows 回环与数据库通过，不代表 Linux TC、可靠 UDP 扩展、真实公网、IPv6、生产负载或物理 iPhone / Shadowrocket 已验收。本次也没有完成全库逐行人工审查，不承诺不存在其他缺陷。
