# Reality 内部握手目标自动选择

状态：本地实现和隔离验收。此文档不表示已经正式发布或升级生产节点。

## 行为

由入口节点测量原内部目标及 Apple、iCloud、Cloudflare、Amazon、Bing、Wikipedia、Google 下载站、Debian、Docker、Hetzner 候选。保持原 SNI、账号、UUID、密钥、Short ID、监听端口、订阅和出口，只选择内部握手目的地。面板原来的 TLS 检测仍只是面板侧初筛；不会被当作节点 Reality 成功证据。

2026-11-23 扩充的四个节点备用目标是 `dl.google.com:443`、`www.debian.org:443`、`www.docker.com:443`、`www.hetzner.com:443`。同一天的本地隔离复测中，它们在固定 Microsoft / Apple SNI 下均成功，但部分目标使用自身 SNI 时出现失败。它们因此仅进入节点备用池，不自动加入面板新建规则的随机 SNI 默认列表。每个生产节点仍须以自身网络、原 SNI 和真实握手结果决定是否选择。

探测使用节点上现有的 Xray 二进制，启动独立的本地测试服务端与共享客户端，以临时身份执行两次 Reality 握手和随机数据回传。不会拿客户身份访问公共网站，不会产生客户计费流量，也不会给节点续期健康状态。

按 SNI、原目标、flow 和客户端版本限制分组。相同配置的数百条规则共用一份结果；不同 SNI 的结果不能互相代替。所有探测都在后台，保存规则和下发不等待网络探测。

## 切换规则

| 情况 | 行为 |
| --- | --- |
| 首次完成一轮 | 在连续两次成功的候选中选择本轮握手延迟最低者 |
| 当前目标两次失败 | 自动转到连续两次成功的最快候选 |
| 当前目标仍健康 | 更快候选同时满足至少快 20%、快 30ms，连续两轮胜出且距上次切换达到 10 分钟后切换 |
| 所有候选失败、探测进程失败、结果不完整或取消 | 保留当前目标和现有转发，不停用客户规则 |
| 节点重启 | 恢复上次选择并重新验证，不把磁盘缓存当作新测量 |

同一配置每轮完成后至少间隔 60 秒，后台每 15 秒检查待测项。每批最多 4 组、28 个目标，同时最多 4 个握手检查，整批上限 90 秒。调度器按目标数量装入完整配置组，不拆分一组的候选结果；当前十个备用目标加原目标时通常每批处理两组，并按最久未检查的顺序轮转。扩充候选不提高进程、连接并发或总时限，不占用保存与下发的同步路径。配置较多时会排队，因此不承诺瞬时故障切换。最多保留 128 组本地转接，超出时该规则继续使用其原配置。

速度指本节点到候选的握手耗时，不是客户下载带宽或 SOCKS5 出口速度。目前候选域名解析优先使用 IPv4 地址、没有 IPv4 时用 IPv6；不宣称穷举每个 CDN 地址或所有客户端指纹。

## 转接与连续性

Xray 原生执行配置将内部 `dest/target` 指向 Agent 本地转接。Linux 使用随机命名的 abstract Unix socket，不占用业务 TCP 端口。Windows 测试环境使用私有 Unix socket，系统不支持时才回退到回环 TCP。

目标切换只改变下一次握手使用的目的地，不重载 Xray，不重写原签名配置或代次。已建立的转接连接保持原目标；认证成功后的业务流量仍直接走原出口，不经过这个转接。转接有总并发和超时限制。

保留原 SNI 意味着某些候选的未认证伪装证书可能与 SNI 不同。通过真实 Reality 认证不等于证明未认证伪装效果，也不是任何网络环境下都可用的保证。

含多个 SNI、PROXY protocol、自定义 socket/transport 设置或未知 Reality 扩展的监听器暂不自动改写，继续保留显式配置，避免简化探测错误批准特殊配置。

## 配置、诊断和回滚

支持的受管 Xray 节点默认启用；`reality_target_auto_disabled: true` 可停用。停用或回滚需在正常节点维护流程中重启 Agent，让其由签名原配置重新生成执行配置。旧版 Agent 不识别该可选配置键，降级时需去掉该键。

节点数据目录下的 `reality-targets.json` 保存当前 SNI、原目标、所选目标、耗时、时间和候选结果，原子替换、权限 0600；不含客户账号、私钥、Short ID、订阅 Token 或出口凭据。选中目标发生变化时写入结构化日志。面板现有节点日志命令附带最多 4 组目标摘要，无新增未鉴权接口。

没有更改 DNS、系统路由、网关、Xray/GOST 版本或客户数据。自动探测不会覆盖管理员暂停或停机状态，也不会恢复被删除的规则。

## 本地验收

- 400 条相同配置只生成一组转接和一批候选探测。
- 全失败、不完整结果、重复结果、未授权候选、取消及探测进程异常保留当前选择。
- 扩大备用池后仍不超过单批 28 个目标，完整探测每一组，多个待测组轮转且不饿死。
- 慢探测不持有配置投影锁；独立连接在目标切换时仍绑定原目标。
- 持久化恢复、固定 SNI 的缓存隔离、特殊设置保留、资源上限及并发检查。
- 使用固定 Xray 26.7.28 的真实回环测试：TCP 可连接但握手失败 → 自动测出可用本地 TLS 目标 → 原账号/密钥/SNI/出口恢复；Xray PID、运行配置、签名代次保持不变。
- Xray 25.10.15 客户端回环兼容性测试。物理 iPhone、小火箭以及生产 Linux/WAN 仍需正式节点升级后的验收。

测试入口：`internal/agent/realitytarget`。设置 `NYVP_XRAY_BINARY` 和可选 `NYVP_OLD_XRAY_BINARY` 运行真实内核测试；所有网络目标均是隔离回环，不连接生产。
