# v0.1.190 — Reality 握手目标自动择优与故障换选

节点自行检测原内部握手目标和十个备用目标，选择在本机网络、原 SNI 和原 flow 下真正可用的目标。修复“端口可通、普通 TLS 正常，Reality 客户端却无法建立连接”中由内部握手目标失效导致的情况。上游 SOCKS5 认证、线路故障和订阅来源错误仍需独立定位。

## 选择机制

- 首轮在两次真实 Reality 认证及随机数据回传均成功的候选中选择握手延迟最低者。
- 当前目标两次失败时切至本轮最快可用项；全部失败、结果不完整或探测进程异常时保留当前配置，不停用客户规则。
- 当前目标健康时，备用项必须至少快 20% 且快 30ms、连续两轮胜出，并距上次切换达到十分钟后才替换；中断的成功记录不能拼成连续两轮。
- 保持原账号、密钥、SNI、监听端口、订阅和出口；目标切换不重载 Xray，已有业务连接继续运行。节点重启恢复上次选择，并重新实测。

## 性能与范围

相同配置的数百条规则共用测量结果。探测在后台按完整配置组轮转，每批最多 28 个目标、4 个并发检查；不会让保存或下发等待远程握手。检测存在轮询时间，不能承诺瞬时故障切换；“最快”指节点握手耗时，不是下载带宽。

新增 Google 下载站、Debian、Docker、Hetzner 仅作为节点备用目的地，不自动成为新规则 SNI。每个候选仍需本机实测，不能把某台机器成功当作所有节点都成功。特殊 socket、多个 SNI、PROXY protocol 等配置保持原样。

## 发布与验收

私有源码、本地保护构建、公开发行包直接上传，不使用付费 GitHub 构建。固定 Xray 26.7.28 和原 GOST，不升级转发内核。面板与 Agent 配套升级才启用完整功能，升级 Agent 时连接可能短暂重连。

逐台检查实际版本、配置回执、旧端口真实转发、目标测量结果、持续流量采样和计量队列。保留升级前备份和原发行包；生产是否完成以该轮部署报告为准，物理 iPhone 仍需用户实测。

更详细的行为及停用方式见 [自动选择说明](reality-target-autoselect.md)。
