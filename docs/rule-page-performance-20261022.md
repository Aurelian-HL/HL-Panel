# 规则列表打开性能修复

日期：2026-10-22。准备 v0.1.136 正式发布；本文的本地数字不代表生产验收结果。

## 实测问题

hlpanel 的规则列表接口连续两次约 30.5 秒后返回 HTTP 504。浏览器页面壳约 1.24 秒返回，但等待首张表格 45 秒仍未完成。离线读取同一份 568 条规则快照，列表计算约 3.3 秒；CPU profile 中重复校验完整节点配置 SHA256 占约 82%。原页面前台每秒重新读取完整列表，多标签页进一步放大负载。

## 修改与边界

- 不可变转发视图构建时对 desired/applied 两代配置各校验一次哈希并准备结构索引。每次读取仍检查规则版本、成员关系、部署 attempt、commit/verify 回执和健康租约；不缓存就绪结论。可变写仓库继续完整校验。
- 锁内借用节点输入，避免逐条规则复制整份节点资源；公开 DTO 继续深复制。
- 同一数据库 MVCC 行的并发冷读合并为一次不可变投影构建，不在请求间共享可变仓库。每次请求仍验证 format_version、revision 和 xmin。
- 快照写事务先解码后加行锁，并在锁内重新核对 MVCC 身份。发生并发写或同 revision 外部修复时，在锁内重读一次；业务回调不重放，流量与健康 overlay 仍在锁后合并。
- 规则页面自动全量刷新改为前台 10 秒、后台 60 秒；保存及启停立即显示结果。在线展示仍使用独立五分钟采样。

不修改规则、订阅、凭据、URL、Reality 材料或节点版本。生产只通过系统更新升级面板，并比较业务身份指纹、验证备份与回滚入口。

## 本地验证

相同离线快照：列表计算 38–39 毫秒，投影准备约 82 毫秒，解码约 277 毫秒。只能据此确认消除了重复 CPU 工作，公网打开速度须在升级后重测。

隔离 PostgreSQL 验证锁外准备不占行锁、并发更新不丢失且不重放、同 revision 不同 xmin 重验证、并发冷读隔离及锁窗口；全量 Go 测试和 vet 通过。前端 360 项测试及构建通过。发布流程还会在 Linux 执行竞态、安装、升级与回滚门禁。
