# HT / HL 转发数据边界（2026-10-30）

## 职责

HT 保存客户联系方式、金额、付款记录、业务到期日及其他运营资料。HL 只保存创建、授权、运行、计量和维护转发所需的数据。HL 不依赖 HT 业务接口维持转发、节点心跳或订阅。

| 数据 | HT | HL |
| --- | --- | --- |
| 客户电话、微信、地址、付款、金额、业务到期日 | 保存和维护 | 新请求不传入 |
| 昵称 | 客户展示和管理 | 可选规则标签，不作为技术关联键 |
| 稳定不透明业务编号 | 保存 | 生成技术身份名并关联规则 |
| 服务身份 ID、规则 ID | 保存映射 | 保存授权、归属和幂等关联 |
| 用户组 / 设备组、入口协议、出口方式、SOCKS5 上游 | 选择和提交必要参数 | 校验和运行 |
| 实际限速、流量策略及运行流量 | 展示和管理 | 按现有规则策略执行、计量 |
| 面板子账号及其权限 | 不与转发客户混用 | 独立管理 |
| 面板软件授权 | 使用独立 issuer 合约 | 不与客户业务到期混用 |

自然到期只供 HT 提醒和统计，不能自动禁用身份、暂停规则或清除连接。普通资料修改、改昵称、续费不触发启停、重建规则或换订阅凭据。管理员明确执行的暂停、恢复、删除仍有效；既有手动停用状态不得因本次迁移或普通续费自动解除。

## 最小创建流程

沿用现有 API，不新增接口，不取消授权检查。所有写操作使用管理员身份和稳定的 `Idempotency-Key`。

### 1. 创建技术服务身份

`POST /api/v1/customers`：

```json
{
  "account_kind": "service",
  "username": "ht_opaque_audit_001",
  "display_name": "规则展示标签",
  "user_group_id": "ugrp_example"
}
```

- `username` 使用稳定、不含联系方式的技术编号，不以电话、微信、邮箱或可变昵称充当关联键。
- `display_name` 可省略；不能借展示字段或备注夹带联系人、金额、到期日。
- `user_group_id` 是现有规则授权依赖，不能因为界面不展示服务身份就删除它。
- 不生成或提交 `password`，服务身份不会因此获得面板登录。
- 不提交 `expires_at`，不按线路数量重复写身份级 `max_rules`、流量和限速；真实运行策略在规则层保留。

### 2. 为身份创建转发规则

`POST /api/v1/customers/{service_owner_id}/forwarding-rules`：

```json
{
  "name": "规则展示标签",
  "entry_group_id": "grp_entry_example",
  "egress_mode": "DIRECT",
  "ingress_protocol": "vless_reality",
  "protocol": "tcp",
  "vless_outbound_mode": "SOCKS5",
  "vless_socks5_host": "landing.example.test",
  "vless_socks5_port": 1080,
  "vless_socks5_username": "upstream-user",
  "vless_socks5_password": "example-only-placeholder",
  "selection_policy": "round_robin"
}
```

示例不含客户资料、到期日、金额、登录密码或重复配额。所选设备组必须已获用户组授权，并配置入口端口范围和可用的自动 Reality 默认值；测试中的域名仅是隔离占位值。SOCKS5 凭据属于运行必要数据，只通过受权写接口传入，不得出现在公开规则响应、审计或一般日志中。

HL 自动分配端口和 Reality 材料。同键同内容重试复用原规则、端口和材料；规则保存成功表示已保存，下发和节点应用仍按实际运行状态判定，不将保存成功当作生产链路已验收。

## 修改与旧记录兼容

- 普通联系方式、金额、业务到期日修改：只写 HT。
- 昵称：只改 HL 展示名，不改技术关联键、入口、端口、UUID、Reality 材料或订阅 token。HL 已将管理版本与运行版本分离，纯展示修改不编译新的节点配置。
- `PUT /api/v1/customers/{id}` 和 `PUT /api/v1/forwarding-rules/{id}` 不是局部 PATCH。先读单条当前记录，用专用请求字段构造更新，并保留原授权、手动停用、实际限速/配额、端口、连接参数及当前 `revision`；不可把 GET 响应直接原样 PUT，也不可只发昵称导致其他字段归零。
- 已经落盘的创建 journal 必须沿用原请求和原幂等键完成重试。不得给同一键替换成新白名单内容，以免产生 409 或重复创建。新 journal 才使用精简白名单。
- 既有到期字段和服务身份不在本次批量清理；旧字段留作兼容，不成为新请求必填项，也不作为转发停止条件。HL 的真实面板子账号权限和面板软件授权不作变更。
- 不删除规则、客户订阅、运行归属或历史映射。删除面板登录与删除服务身份仍分别遵循 `deletion-contract-20261021.md`。

## 后续发布顺序

本轮只完成本地候选，不立即发布。集中发布时，先确认目标 HL 已支持 `account_kind=service` 与上述最小请求，再切换 HT 新建流程。旧 HL 若拒绝此合约，应明确显示版本不兼容；不得退回生成登录密码、复制业务到期日，或为同一操作换键重复创建。

既有未确认 journal 继续使用原请求和原幂等键，不因候选升级自动重写；历史字段不在此次批量清理范围。生产现有规则、订阅、节点运行与面板软件授权保持各自原有合约。

## HL 本地验证

`internal/control/httpapi/service_owner_minimal_contract_test.go` 使用实际 HTTP handler 校验上述两个 JSON 请求：身份无密码、无业务到期和重复配额；服务身份不能面板登录；VLESS Reality / SOCKS5 创建及同键重试正确；公开响应和审计不泄露运行密码。

同时复用已有回归验证：纯展示修改不生成新节点配置；删除面板登录不删除规则；过期提醒不影响转发；旧生成密码请求仍保持原幂等摘要。测试全部在本地隔离存储中运行，不访问生产节点。HT 候选改动及联合核查结果另见本轮验收记录，完成本地核查不代表已发布或升级生产。
