# 面板登录账号与线路身份分离

日期：2026-10-22。当前状态：本地实现和隔离验收完成，准备 v0.1.134 正式发行；生产部署与定向登录清理须在 Linux 发布门禁通过后执行。

v0.1.133 标签保留但未正式发布：第二轮 Linux 检查中，新装、真实引擎、网页更新和迁移通过；保留配置的升级验收漏列了本轮新增的两个受管 `/account/` 路由，因此 Ubuntu 22.04/24.04 均被配置指纹门禁阻止。v0.1.134 将两个精确受管路由加入允许差异，继续逐字节核对其他配置，并新增真实 Nginx 登录入口和 no-store 响应验收；不扩大生产配置修改范围。

## 本轮边界

- 用户管理只列出拥有面板登录凭据的子账号；线路业务身份继续独立存在。
- 删除子账号只删除登录凭据并撤销该账号全部会话，不删除或停用业务身份。
- 规则、订阅及 URL、VLESS 凭据、运行材料、节点配置及配置 generation 必须保持不变。
- 本轮先完成登录身份分离，不增加配额、限速或授权组的新执行机制，不调整 HT，不升级节点或 Xray。
- `hlpanel.hongle.cc` 的目标是只保留超级管理员 `admin`，清空所有子账号登录身份。用户已经明确授权该范围；规则、订阅及 HT 开通记录所需的业务 owner 不能删除。不得将这项站点清理推广到其他面板。

## 数据与接口

快照格式由 24 升为 25。独立的 `PanelAccounts` 注册表保存面板密码哈希，以稳定的业务 owner ID 关联 `Customers`；业务 owner 不再保存登录密码哈希。会话鉴权必须确认登录注册表仍有该账号。

通用升级读取旧快照时，将已有合法密码哈希迁入注册表，保留原 ID、密码验证能力及有效会话，避免其他面板的合法子账号失去访问权限。对 `hlpanel.hongle.cc`，升级分离版后按用户授权逐条撤销全部迁移登录身份及其会话；超级管理员位于独立注册表，不在清理范围内。旧快照兼容不代表本面板需要保留这些登录。

`GET /api/v1/customers` 保持返回全量业务身份以兼容既有调用；用户管理改为请求 `?account_kind=panel`。`?account_kind=service` 可读取无登录权限的线路身份。API 从不返回密码哈希。

只有明确提交 `account_kind=panel` 才能创建子账号，且要求密码；用户管理页面已显式提交该类型。未传类型的旧接口调用默认创建纯线路身份，历史调用附带的生成密码不赋予登录、不保存密码哈希；不传密码也可以创建业务身份。显式提交 `account_kind=service` 时不得提供密码。

旧接口更新纯线路身份时，附带的历史生成密码同样不赋予登录；业务字段按原规则更新。创建和更新均保留旧格式的请求指纹，旧幂等请求不会重复创建业务 owner，已撤销的登录也不会因重试复活。编辑不能转换身份类型。

删除后原业务用户名继续保留唯一性，不能用同名新账号接管旧规则。业务 owner 上原有配额、用量和组关系继续保留；本轮拆分的是凭据与删除生命周期，不宣称已完成权限策略的进一步拆分。

子账号登录入口为 `/account/login`，打包至 `web-admin/account`。登录后进入页面会校验服务端会话；撤销凭据后旧令牌返回 401，页面退出至登录入口。
