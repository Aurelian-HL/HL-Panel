# NY 官方功能与日常流程核对

核对日期：2026-10-02。范围：只读访问 `https://nyanpass.pages.dev/` 及其公开搜索索引；未访问、登录或修改三个受保护站点。本文没有把公共文档当成已获得的 NY 后端源代码，也不代表完成 NY 重构。

## 1. 本轮结论

目前的“节点注册、设备组、配置代数、端点池”主要是开发者控制面，并不等于 NY 用户每天使用的“用户、用户组、转发规则、规则分组、入口/出口设备组、流量统计、资源限制、节点探针、套餐订单”。只有底层设施，缺少这些业务闭环，用户认为偏差大是有依据的。

必须先以 NY 的业务操作为主线恢复功能，再把 VLESS 加入同一套用户、设备组、规则、统计和限额流程。不能把新协议演示平台改个名称就视为 NY 重构，也不能用菜单占位代表功能已实现。

NY 是通用转发管理系统，不能概括成“只支持 SOCKS5 的面板”。SOCKS5 可以是被转发到的落地服务；NY 的 TCP/UDP 规则、入口/出口隧道及其 `ws/http/tls` 承载是另外的层次。[官方介绍](https://nyanpass.pages.dev/intro/#_4)、[连接信息](https://nyanpass.pages.dev/reference/connect/)。

## 3. 必须保留的语义，不能只还原表单

### 3.1 用户、用户组与资源授权

用户组不是设备组，也不是规则分组。设备组对用户组授权决定可用资源；备用出口不能绕过用户组权限。用户过期或额度不足时，规则不在可同步范围内。[规则同步](https://nyanpass.pages.dev/reference/forward_rule/#_5)、[备用组权限](https://nyanpass.pages.dev/reference/be_dg/#_4)。

公开文档没有给出用户全部字段、用户组的全部权限结构、套餐授权合并规则、流量重置日与自动续费优先级。实现前必须取得脱敏导出或授权的只读界面证据，不能把推测当成 NY 兼容字段。

### 3.2 规则发布状态

官方规则创建时为“未同步”；入口同步后为“正常”或“同步失败”。入口和出口各自同步，周期约 20 秒，单规则变更会尝试 gRPC 即时推送但不保证成功。端口被占用是同步失败的常见原因。[同步过程](https://nyanpass.pages.dev/reference/forward_rule/#_5)。

新平台可以采用更可靠的配置版本机制，但用户需要直接看到规则是否生效、在哪个节点失败、为什么失败、能否重试。仅显示 `generation/applied` 数字不能替代规则业务状态。规则保存成功也不能立即标记为转发正常。

### 3.3 流量实际值与扣量值

官方例子：下载 500 MB、上传 100 MB，入口倍率 1.5，出口倍率 0.5：

- 规则实际使用流量为 600 MB，由入口上报，出口不再重复计入规则统计。
- 用户额度扣减为 `600 × 1.5 + 600 × 0.5 = 1200 MB`。
- 用户当日实际使用统计为 600 MB。
- 入口组和出口组各自增加约 600 MB 实际流量。
- 探针网卡收发值有自己的统计范围，不等于用户账本。

出处：[倍率说明](https://nyanpass.pages.dev/reference/forward_rule/#_6)、[探针统计口径](https://nyanpass.pages.dev/reference/node_status/#_3)。新模型必须分开保存原始计量与额度扣减，并保留使用时的倍率；不能把双跳流量合并成双倍实际用量，也不能用当前倍率随意重算历史扣量。

### 3.4 限速、IP 和连接数

官方明确每个入口独立计算，而非“通常单入口”。同一个用户在入口 A 与 B 可以各享其用户限速；同一入口下该用户多条规则共享用户限速，规则另有自己的上限。IP 与连接数亦采用这一叠加方式。UDP 不支持这些限制，整台入口程序总速度也无法通过该功能限制。[资源限制](https://nyanpass.pages.dev/reference/nc_speed_limit/)。

新平台若实现跨入口总配额或集中调度下的总限速，属于明确的新功能，不应称为照搬 NY 行为。

### 3.5 单链接与设备组

用户要求的“一条 VLESS URI、组内多台机器按连接调度、故障节点退出”是 NY 入口组能力上的新增要求。NY 入口组只共享规则，不自带这段负载。新平台需在保留入口/出口选择和权限语义的同时，增加稳定接入地址及服务端调度。

后台可以维护多个节点，但客户不能收到由组成员展开成的十条节点链接。这个约束来自本项目用户要求，不是 NY 官方现成功能。

### 3.6 TLS、Reality 与 Vision 边界

NY 的 TLS 入站在入口终结 TLS；SNI 母/子规则明确不兼容 VLESS-Vision、VLESS-Reality、ShadowTLS。[SNI 分流](https://nyanpass.pages.dev/reference/sni_split/)。因此，`VLESS_TLS`、`VLESS_VISION`、`VLESS_REALITY` 与旧式 TLS 终结规则必须被配置编译器区别处理，不能把所有名称中带 TLS 的功能混成一个开关。

## 4. 建议恢复的日常业务流程

以下是按官方行为整理的新平台交互建议，不是假称已经读取到的 NY 精确菜单。

### 4.1 先把机器组成资源，再给用户配置规则

1. “设备组”创建入口组、出口组；设置名称、允许端口范围、用户组权限、入口直出策略、允许出口、倍率及协议选项。
2. 在组内点“对接”，获得在线安装命令或离线安装包；同一组的多台机器使用同一组对接信息。官方现有流程确实是“设备组 → 对接 → 在线/离线”。[节点安装](https://nyanpass.pages.dev/intro/nodeclient/#_4)。新平台仍应保持每台节点独立凭据，不能为操作方便共享长期密钥。
3. “节点状态”查看机器归属、在线状态、资源、网络、版本、规则同步失败；从组进入应自动过滤该组。
4. “用户/用户组”配置用户、到期、额度与可使用的资源；流量和限制直接可见。
5. “转发规则”选择所属用户、规则分组、入口设备组、出口组或入口直出、监听端口、目标列表、目标选择策略、规则限制。
6. 保存后看到未同步、正常、失败及失败节点；可复制接入地址、批量导出和批量管理。
7. “流量统计”按用户、规则、组和时间查实际用量，区分已用额度与倍率扣量。

### 4.2 在同一个规则/服务流程里加 VLESS

传统规则继续保留；新增“客户接入协议：VLESS TLS / Vision / Reality”后，根据协议展示必要参数。用户仍选择用户、入口组、直出/出口组/SOCKS5 落地、限额与到期。

“同组 10 台，直入直出”的结果应是一条固定域名、端口和客户凭据对应的 VLESS 链接；组成员变动不要求客户替换链接。内部的端点池、生成器、秘密引用和发布代数放进高级详情，不能成为用户开通业务必须手工拼装的流程。

服务必须在身份、配置、节点确认与接入探测都满足条件后才显示“可用”；否则提供明确原因，不生成看似正式可用的链接。

### 4.3 原有规则批量导入

入口页先区分“NY 批量规则导入”和“整站迁移”。前者至少支持官方旧文本：

```text
名称#监听端口#目标地址#目标端口
名称##目标地址#目标端口
```

后者不能用旧文本替代，必须保存用户、组、权限、倍率、目标策略与引用关系。官方 JSON 详细结构在公开页未给出，只确认“批量导出生成”，因此应使用真实脱敏样本锁定版本，而非自行猜 schema。[批量格式](https://nyanpass.pages.dev/reference/forward_rule/#_4)。

导入步骤应为：选择来源 → 上传/粘贴 → 展示逐行解析、权限和端口冲突 → 映射新资源 → 确认导入到新平台 → 查看新节点应用结果。迁移源全程只读。

NY 的 `-copy-database` 会覆盖目标数据库，官方明确不可恢复；它不是新平台安全合并导入器，不能直接拿来执行跨平台迁移。[数据库拷贝](https://nyanpass.pages.dev/reference/be_command/#_6)。

## 6. 不能仅凭公开文档补齐的部分

- 用户当前安装版本的实际菜单、弹窗字段、表格列、排序和默认值。

- 仪表盘、用户/规则批量操作、站点设置中的全部页面行为。

下一步应优先读取已经下载到本地的 NY 前端/脱敏快照，或在既有授权范围内只读查看对应页面。外观与业务对齐需要这份页面证据；新增 VLESS 和底层协议替换则需由新平台自己实现并端到端验收。官方明确暂未提供稳定 API 文档，前端源码需从售后渠道获取：[API 说明](https://nyanpass.pages.dev/reference/personalization/#api)。
