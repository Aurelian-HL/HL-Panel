# NY 离线导入预检契约

## 目标与硬边界

该模块只负责对管理员已取得的本地 NY 快照做只读结构预检，为后续洁净室迁移建立证据链。它不是在线同步器，也不是导入执行器。

- `zf.hongle.work`、`kl.hongle.cc`、`ht.hongle.work` 必须持续提供现有服务。
- 允许人工只读查看公开页面或下载已授权导出；禁止预检器登录、爬取客户信息、调用生产写接口或绕过权限。
- 禁止修改生产数据库、配置、DNS、端口和进程；禁止覆盖部署、重启、压力测试或故障演练。
- 输入只能是绝对路径普通文件。在 Windows 上，UNC、映射网络盘、设备/扩展命名空间、保留设备名、ADS、符号链接和重解析路径都会在读取前拒绝。
- 原始快照不被修改；程序持有自己的字节副本并计算 SHA-256。
- 报告不输出原始规则、地址、名称、用户名、密码、Token 或证书内容。无可信 schema 时，连 JSON key 和字段路径也只输出稳定 SHA-256；只有经仓库评审的适配器才能输出其受控 schema 路径。

正式导入、对象创建、映射写入、节点配置发布和生产切换均不属于本模块。后续若实现，必须是单独的、可审计且有事务与回滚的流程。

路径防护边界：当前 Windows 实现会检查卷类型和每级重解析属性；非 Windows 实现只拒绝路径组件中的符号链接，不能识别挂载在普通目录下的 NFS/SMB 等远程文件系统。本地预检假定快照及报告父目录由操作者控制，检查与打开之间不存在恶意并发替换；不满足该假设时应先复制到受控的本机临时卷再运行。

## 当前真实支持状态

当前没有注册任何 NY schema 适配器。

原因是尚未取得可核验的 NY 全量 JSON 导出样例、对应面板版本和版本化 schema。程序不会根据字段名、页面文案或相似项目的数据结构猜测 NY 格式：

- 未声明 schema 时返回 `schema_required`；
- 声明了 family/version 但没有已注册的精确版本适配器时返回 `unsupported`；
- JSON 语法错误或危险 ZIP 返回 `invalid_snapshot`；
- JSON 对象中重复的字段（包含转义后相同的字段名）和超过 256 层的嵌套也返回 `invalid_snapshot`，在适配器读取前阻断；
- 只有精确版本适配器被显式编译注册且成功预检时才能返回 `preview_ready`。

因此当前产物只是版本化的**标准化中间预检报告**，用于保存快照哈希、结构清单和证据缺口；它不是 NY 原生导入结果，也不能作为已迁移、已兼容或可写入业务库的证明。

本地 `flux-panel` 源码可以证明其转发文本格式为：

```text
remoteAddr|name|inPort
```

这只是 Flux Panel 自己的源码证据，不是 NY JSON schema，也不会被注册为 NY 适配器。

## 预检结果

报告版本当前为 `3`（新增 JSON 嵌套结构清单；读取旧报告的程序应显式处理版本差异），主要字段如下：

| 字段 | 含义 |
|---|---|
| `status` | `preview_ready`、`schema_required`、`unsupported` 或 `invalid_snapshot` |
| `snapshot` | 输入字节数、格式和 SHA-256，不含原文 |
| `schema` | 外部明确声明的 family/version、是否存在注册适配器，以及该适配器声明的证据元数据数量 |
| `top_level_kind` | JSON 顶层为 object、array 或 scalar |
| `top_level_field_fingerprints` | 排序后的顶层 JSON key SHA-256；不回显不可信 key |
| `json_structure` | 仅合法 JSON 提供：最多 1024 项的路径 SHA-256、JSON 类型及出现次数；数组下标统一为通配段，混合类型分别计数；达到上限时 `truncated=true` 并给出警告 |
| `groups` / `rules` | 脱敏计数和对象指纹；无 schema 时固定为未解释、数量 0 |
| `mappings` | 精确适配器的只读映射提案；无 schema 时为空，绝非数据库写入计划 |
| `reference_conflicts` | 规则到组等引用冲突，只保留类型、字段、警告码和对象指纹 |
| `unsupported_fields` | 只输出路径 SHA-256 和受控原因码；适配器路径文本也会先哈希 |
| `issues` | 稳定警告码、级别和不含源数据的说明 |
| `archive` | ZIP 清单统计、展开大小和文件名 SHA-256，不含文件名及内容 |

嵌套结构清单只用于比较授权导出样本的形状，不识别 `groups`、`rules` 等业务字段，也不是 schema、映射或兼容性证明。对象键作为带长度的内部路径段参与哈希；数组元素共用一个路径，不回显下标、原始字段名或值。不同类型占不同清单项，出现次数是该路径和类型在整个快照中的计数；超过上限后的新路径不入清单，因此截断报告不可视为完整字段全集。即便 JSON 顶层存在 `groups` 或 `rules`，没有适配器时也不会据此生成组和规则。SHA-256 仍可能遭受已知词典猜测，因此报告不是秘密存储，仍应按迁移证据保护。

映射提案只使用来源对象 SHA-256 指纹，不含名称或目标数据库 ID。每个已识别组/规则必须恰好有一条提案。可提案的设备组必须标明 `ENTRY` 或 `EXIT`；可提案的规则必须有可提案的入口组，且明确为 `DIRECT`（不带出口组）或 `EXIT_GROUP`（引用可提案的出口组）。缺组引用等冲突会阻断对应规则提案；未支持的字段或语义可标为 `blocked` 并给出受控原因码。`proposed` 只表示来源结构可映射到目标概念，**不表示现有目标数据无冲突，也不表示可以提交、已激活或已验证转发**。持久化导入仍需另行设计目标状态比对、权限、幂等提交、事务审计和回滚。

## ZIP 预检

首版仅对 ZIP 做清单预检，不解压到磁盘，也不自动选择其中某个 JSON：

- 默认最多 512 个条目；
- 单条目声明展开大小最多 32 MiB；
- 总声明展开大小最多 128 MiB；
- 拒绝绝对路径、`../` 越界、符号链接和加密条目；
- 报告只保存条目名称的 SHA-256、压缩/展开大小、目录标记和 JSON 候选计数。

ZIP 中存在 `.json` 只代表“可能是 JSON 文件”，不代表它是 NY 导出，更不代表可以导入。

## Schema 适配器准入

产品准入要求一个 NY 适配器同时具备：

1. 精确 `family` 和 `version`，不得按字段形状模糊匹配；
2. 非空证据引用；
3. 被引用 schema/样例的 SHA-256；
4. 合法、非法、缺字段、未知字段和悬空引用的契约测试；
5. 仅返回脱敏对象指纹、数量、映射提案、冲突和不支持字段；禁止透传任意诊断文本；
6. 证明同一快照重复预检结果确定，且不修改原始快照。

需要准确区分运行时检查与工程审查：

- 运行时注册当前只能检查 family/version 是否完整、证据引用是否非空、SHA-256 文本格式是否合法，以及同版本是否重复；
- 运行时不会联网获取引用内容，也不能证明该摘要确实对应官方 schema、真实导出或完整契约测试；
- schema 原件、摘要匹配、来源真实性和测试覆盖必须由仓库评审及 CI 在适配器编译注册前验证；
- `preview_ready` 仅表示一个已注册适配器接受了快照，不单独证明 NY 原生兼容、可正式导入或可上线。

发现新字段或版本变化时默认阻断，不自动兼容。

## 命令行

入口：`apps/ny-import-preview`。

先编译临时可执行文件，以便准确取得应用自身的 `0/1/2` 退出码：

```powershell
go build -o "$env:TEMP\ny-import-preview.exe" ./apps/ny-import-preview
```

输出到标准输出：

```powershell
& "$env:TEMP\ny-import-preview.exe" -input C:\snapshots\ny-export.json -report -
$LASTEXITCODE
```

写入一个全新的报告文件：

```powershell
& "$env:TEMP\ny-import-preview.exe" `
  -input C:\snapshots\ny-export.json `
  -report C:\snapshots\ny-export.preflight.json
```

报告文件必须是绝对路径并使用“仅新建、不覆盖”语义；Windows 会拒绝相对路径、UNC、网络盘、设备路径和重解析父目录，路径已存在时命令失败，避免覆盖证据或原始快照。非 Windows 远程挂载限制同上。

只有已有仓库评审并注册的精确版本适配器时才可同时声明 schema：

```powershell
& "$env:TEMP\ny-import-preview.exe" `
  -input C:\snapshots\ny-export.json `
  -schema-family ny-json `
  -schema-version exact-version `
  -report -
```

当前没有 NY 适配器，因此上述声明会真实返回 `unsupported`，不会伪造兼容结果。

退出码：

| 退出码 | 含义 |
|---|---|
| `0` | 已注册的精确版本适配器成功完成脱敏预检；不等于允许正式导入 |
| `1` | 参数、读取、JSON/ZIP、安全检查或报告写入失败 |
| `2` | 快照结构可读取，但缺 schema 或该 schema 不受支持 |

退出码 `2` 仍会生成报告，便于保存 SHA-256、字段清单和缺失证据原因。

`go run` 会把子程序的退出码 `2` 包装成 Go 工具自身的非零退出并打印 `exit status 2`，PowerShell 看到的 `$LASTEXITCODE` 可能是 `1`。需要核验契约退出码时必须运行编译后的可执行文件。

## 已验证项目

本地隔离测试覆盖：

- 空输入和超限输入；
- 非法 JSON 和多个顶层 JSON 值；
- 顶层/嵌套重复字段、转义同名字段、跨对象同名字段和嵌套深度上限；
- 未声明、声明不完整和未知 schema；
- 不可信 JSON key 和未知字段路径只报告 SHA-256，不回显包含密码、Token 或地址的 key；
- 嵌套对象、数组、混合类型的脱敏结构计数、稳定排序、容量截断，以及非法 JSON 不生成部分清单；
- SHA-256 确定性和原始快照不可变；
- 适配器必须声明证据引用且摘要文本格式正确；测试不把这项元数据校验表述为来源真实性验证；
- 组、规则、引用冲突和不支持字段的脱敏适配器契约；
- 映射提案的完整覆盖、入口/出口组角色、直出和经出口组路径校验，以及适配器诊断文本脱敏；
- ZIP 文件名/内容不泄露、路径穿越和展开大小限制；
- 标准输出、显式报告路径和禁止覆盖已有报告。
- Windows 本地绝对普通文件可读取；相对路径、UNC、网络盘、设备命名空间、保留设备名、ADS、符号链接和重解析路径设有拒绝检查。非 Windows 代码包含符号链接拒绝，Linux 交叉构建通过，但尚未在 Linux 运行测试，也不宣称能识别 NFS/SMB 普通挂载。实际符号链接测试若因 Windows 权限跳过，须以最终验证记录为准。

这些测试全部使用临时本地文件，不连接三个线上站点或任何生产系统。
