# 控制面性能维护

## 高频写入

协议探测的首次激活仍在正常业务事务中写入快照和审计。后续健康续期只保存已验证的协议凭据，并更新快照修订号；不重复编码和写入完整业务快照。凭据与业务编辑使用相同的数据库行锁，业务写入时原子合并并清理增量记录。

健康恢复不会延长租约，不会用 TCP 连通代替协议验证。旧配置的探测结果仍会被拒绝。迁移导出包含已提交的最新凭据，导入会清除目标机器残留的增量凭据，并按迁移规则重新验证健康状态。

已删除节点保留历史记录，但不会继续编译新配置、领取配置或提交应用回执。历史失败记录不能作为正在承载流量的证据。

## 流量查询

迁移 `000007_usage_query_totals` 为每个节点、用户、规则和入口/出口组合维护全时段与 UTC 自然月汇总。写入、修改、删除与汇总在同一 PostgreSQL 事务内完成；重复上报不重复计费。按节点分散汇总行，避免所有上报争用一个站点计数器。

全时段和完整 UTC 自然月查询使用精确汇总，任意时间范围继续读取原始账本。汇总和明细分页共享只读可重复读事务，保证结果一致。流量额度与历史明细均保留，汇总不是估算缓存。

旧面板升级会对已有账本进行一次回填。正式更新器先备份并暂停控制面后迁移；节点保留最后可用配置。回填时间随数据量和磁盘性能变化，请预留维护窗口。失败时使用更新器生成的回滚命令恢复程序及数据库；不要手工删除流量表。

## 验证与测量

集成测试覆盖续期不改快照 payload、并发业务写入、旧凭据拒绝、数据库失败回滚、迁移恢复、历史账本回填、重复上报、索引缺失以及各统计范围与原始账本的精确对照。

百万条测量只在隔离的本地 PostgreSQL 数据库运行：

```powershell
$env:NYVP_TEST_POSTGRES_URL = 'postgres://postgres@127.0.0.1:55432/nyvp_performance_test?sslmode=disable'
$env:NYVP_TEST_POSTGRES_ALLOW_MUTATION = 'true'
$env:HL_TEST_MILLION_USAGE = 'true'
go test ./internal/control/usage/postgres -run TestQueryTotalsMillionEventMeasurement -count=1 -v
```

一次本地测量中，100 万条账本投影为 600 行；全站汇总从 135.547 ms 降至 0.126 ms，两者返回完全相同的统计。该结果只说明该数据集的查询性能，不代表所有环境或整机 CPU 降幅。

上线后应在相近业务负载下分别测量 API、数据库 CPU、内存和快照写入频率。首次启动、备份、迁移期间的短时负载不应与稳定运行期直接比较。业务快照仍会在配置、账号和其他低频业务修改时整体写入；任意时间范围及深分页仍有原始账本读取成本。
