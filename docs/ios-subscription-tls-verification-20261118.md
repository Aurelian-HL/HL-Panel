# 苹果订阅 HTTPS：调查与防护进展

[项目介绍](../README.md) · [更新路线图](../ROADMAP.md#a2--收敛苹果设备间歇-https-失败)

核对日期：2026-11-18。**偶发失败的根因仍待定位；证书激活防护已通过本地测试，尚未发行或部署。** 本页不公开生产域名、订阅地址、设备标识或完整访问日志。

## 当前结论

部分苹果设备曾间歇出现订阅或 Safari 安全连接失败，当前可以使用但偶有复发。仅凭这一提示，不能确定是手机时间、运营商、客户端、证书或转发内核引起。

订阅通过 HTTPS 下载成功与代理连接成功是两条验收路径，需分别检查。

## 已完成的检查

- 当次证书链及有效期检查正常，TLS 1.2 / 1.3、HTTP/1.1 / HTTP/2 抽测成功。
- 桌面工具模拟三类 Safari 握手，分别请求公共接口及两种订阅格式，18 项检查成功；这不代表真实 iPhone 的系统信任实现和蜂窝链路已验收。
- 脱敏日志中的 10 次错误发生于 keepalive 或 HTTP/2 读取阶段。缺少原设备准确失败时间，不能把这些记录直接关联到用户的故障，也不能据此排除握手问题。

## 已补充的防护

候选域名证书在激活前增加有效期、域名、服务端用途和完整信任链校验，并核对私钥。检查失败时不切换活动证书，也不 reload Nginx；没有关闭证书验证或改变转发内核。

11 项真实 OpenSSL 隔离用例通过：EC / RSA 完整受信链接受；缺失中间证书、过期、尚未生效、用途错误、域名错误、私钥不匹配、加密私钥、损坏证书及自带根授信均拒绝。订阅包测试、Shell 语法和差异检查通过。

**这项防护尚未被证明是偶发连接失败的根因修复。** 现有安装的证书助手不会仅因普通面板升级而自动替换，存量助手的升级和恢复衔接仍待实现与验收。
