# v0.1.186 — 流量积压恢复与升级验收

在线心跳不能证明流量统计正常。本版继承订阅来源校验、取消周期健康证明门槛、独立采样和批量补报，并补上大规模积压恢复及逐台升级的验收约束。

## 修复内容

- **采样不再等待旧报告发送完。** 旧报告超时重试时，新规则的计数仍按采样周期落盘。
- **积压连续批量补报。** 每批最多 128 条，成功后继续清理积压，无需再等完整采样间隔。仅删除服务器已确认的连续前缀；回执丢失后重发保持幂等，不重复累计。
- **订阅来源清楚可查。** 原规则、凭据或入口已删除时显示具体原因。保留历史身份，不自动把同名、同端口的新规则绑给旧订阅。
- **升级验收增加计量进度。** 连续观察至少两个采样周期；采样时间必须至少前进两次，升级前的积压必须全部得到确认，计量流标识和序列不得回退。新流量仍在产生时，允许队列短暂包含最新采样。
- **遇到问题先停止。** 未解决的问题阻止正式发布或继续下一台；修复后使用新版本重新构建，不覆盖已经标记的旧包。

## 验证范围

- 使用合成数据复现 2724 条旧报告、500 条规则持续采样、服务端已提交但回执丢失、重启后重放的完整过程。最终 3724 条计量合计 458052 字节，不重复、不丢失。
- 独立采样、积压连续发送，以及上述恢复过程均覆盖并发检查。测试总时限与采样独立性的 3 秒断言分别设置，不改变生产请求超时。
- 在隔离 PostgreSQL 中验证 2724 条记录的四种组合：有无配置代次、明细或仅累计；各组合完整重放后均累计 272400 字节。
- 验收工具拒绝“仅在线但采样停滞”、旧积压未清完、队列被重置、计量序列回退，以及只采样不发送等情况。

这些是本地验证范围。正式包仍需通过完整 CI；生产端是否恢复，以逐台采样、积压、真实转发和订阅验收记录为准。

## 发布与升级

v0.1.185 构建因新增积压问题排查而取消。v0.1.186 构建期间又发现心跳反复重排下发任务的问题，也已取消。两版均未正式发布、未部署；相关修复汇入 [v0.1.187](release-v0.1.187.md)。

顺序为先面板、后该面板所属节点，逐台确认后继续；本次三套环境按 QWE、AAA1、HL 顺序，HL 最后。先保留必要备份与回滚路径，保留流量队列、客户累计、节点身份和原订阅身份。仅升级面板不能启用节点端独立采样。

Xray / GOST 核心不升级。Agent 维护可能短暂中断被操作节点的连接，TCP 连接不能原地迁移，客户端需要重连。上游或节点与面板之间的实际网络故障仍需单独修复；不以清空积压、伪造回执或返回空订阅掩盖失败。
