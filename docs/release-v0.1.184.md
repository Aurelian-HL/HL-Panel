# v0.1.184 — 流量持续采样与批量补报

修复规则增加、网络抖动或历史报告积压时，新规则流量迟迟不更新的问题；同时包含取消周期协议健康验证门槛的修复。

## 本轮修复

- **采样持续进行。** 节点采样独立于网络发送，旧报告重试期间仍采集新规则计数并写入有界本地队列。远端请求不再占用配置应用的生命周期锁。
- **积压连续补报。** 新增批量计量接口，每批最多 128 条、请求体最多 1 MiB；一批成功后立即处理下一批。长批次在条目边界返回已提交结果，避免长期占用请求。
- **确认进度可靠保存。** 仅移除面板已真实确认的连续报告，断线与重启可幂等重放；不清空积压，不凭空修改客户累计。
- **新旧版本兼容。** 旧面板缺少批量接口时自动使用单条接口，每 32 条保存确认进度；每 5 分钟重新探测批量能力。
- **降低大规则集的计量开销。** 同一批次内复用相同配置的解析结果；每条仍读取并核对配置代次、实际内容、应用回执、撤销状态、归属及幂等序号。解析缓存不跨请求且限制为一份不超过 4 MiB 的配置。
- **取消周期验证等待。** 不再因 90 秒协议探测证明过期，把实际已部署规则撤回为未就绪。暂停、额度、零权重、退役、身份认证和实际配置应用回执仍生效；修改端口不能借用旧回执。

## 验证范围

- 全仓库 Go 测试通过，定向并发检测通过。
- 真实 TLS 批量接口覆盖 600 条绑定配置代次的报告、完整重放，以及批次中途回执失效后仅确认已提交前缀。
- 隔离 PostgreSQL 覆盖普通/绑定代次 × 明细/仅累计四种组合，各 600 条补报后得到 600 条规则、60000 字节和游标 600；重放不重复累计。
- 本地 600 条配置校验中位数从约 1.39 秒降到 0.20 秒，该环节内存分配减少约 98%。这是配置校验基准，**不是完整下发耗时或公网提速保证**。
- 正式发行仍须通过完整构建、真实引擎兼容、安装、更新和回滚验收。最终结果以发行记录对应的 CI 为准。

## 更新顺序与边界

**先更新面板，再逐台更新 Agent。** 只更新面板无法启用节点独立采样与快速补报；仅更新 Agent 可兼容旧面板，但仍使用单条上报。

Xray / GOST 核心版本不变。独立部署的 `connection-gateway` 需更新对应程序，才能取消其本地旧证明期限限制。节点维护可能中断该节点现有连接，安排更新时应逐台执行，并保留原程序与计量队列。

网络中断期间面板统计仍会滞后；队列受本地容量与磁盘约束。此次修复不会代替修复真实的节点到面板网络故障，也不解决上游账号拒绝、业务端口未监听等问题。生产升级、积压消退和真实客户端转发需单独验收。

源码及历史继续保存在私有仓库；公开仓库仅提供交付文件和正式二进制包。
