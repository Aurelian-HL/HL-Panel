# v0.1.193 — 安装恢复、批量操作与订阅一致性修复

本版集中修复从新机安装到日常规则管理的边界问题。使用本地保护构建；Xray / GOST 沿用既有固定版本，不使用付费 GitHub 构建。

- **新机安装更完整。** 首次下载前检查系统、权限与必要依赖；下载只接受 HTTPS，并设置连接、时长和大小上限。固定本次使用的发布版本，避免安装过程中前后文件来自不同版本。
- **坏包提前拒绝。** 解压前检查越界路径、软硬链接、重复文件、文件数量和解压总大小；逐文件校验摘要，拒绝未列入校验清单的文件。该校验不能替代尚未实现的独立发行签名。
- **失败回滚顺序修正。** 新机安装失败时，先清理本次创建且带标记的数据库及角色，再恢复 PostgreSQL 原服务状态，避免数据库先停止后残留半安装状态。
- **SK5 账号不再被悄悄改写。** 单条编辑、批量创建、导入和数据库恢复统一保留账号密码中的合法空格、冒号及 URL 转义字符。只改昵称不应改变上游账号，也不应引起无关的运行配置更新。
- **批量导入按真实运行状态提交。** 补齐 SOCKS5 私密凭据及隧道传输字段；保留已有身份和必要运行材料。预览与提交使用一致的校验，冲突或编译失败整批回滚，越界批次提前拒绝，预览不回显私密凭据。
- **批量导出可以正确重试。** 修复部分条目失败后反复返回旧失败结果的问题；明确失败的批次可重新生成，成功的已有订阅继续复用。网络结果不明时仍保留原请求标识，避免重复创建。
- **已授权规则能生成原订阅。** 补齐受委派管理规则的订阅生成、批量导出和名称同步，同时保留管理员之间的权限隔离。
- **删除导入规则不再留下无效关联。** 无独立客户的导入规则不再误走客户恢复归档；删除时同步移除其自动订阅，失败整笔回滚。真实客户的原订阅和恢复能力不因此被清空。
- **客户状态与限额及时进入下发链路。** 停用、限速、IP 数或连接数修改会在同一事务提交受影响节点的配置更新；纯备注或密码修改不产生无关的节点配置。
- **重置密码与停用会撤销旧登录。** 密码重置、停用和会话撤销一起落库；重新启用不会恢复停用前的旧会话，幂等重试不误删后来新建的会话。
- **修正大规模端口预留的误报。** 节点与本机维护助手改为一次有界读取完整内核端口列表，避免稀疏列表超过读取缓冲区后被截断，误报“端口预留并发变化”并阻止下发；继续保留其他程序的预留端口。此项需要更新受影响节点及其维护助手后生效。
- **解除旧尾流量堵住新规则的问题。** 旧节点在删除规则后可能仍上报尾流量；若中间配置只有准备回执，旧校验会拒收并导致队列积满、新规则等待。现在仅在删除已有真实回执、相邻历史规则完全相同且能追溯到已验证配置时补齐计量归属；不跳过用量、不清空队列、不放行未验证的现用规则，原有防重复计费仍保留。

## 更新与验收边界

上述修复以控制面、前端及安装脚本为主。本地单元、隔离数据库和包完整性验证的通过，不等同于 Linux systemd 全链路或真实客户端已验收。正式切换前应逐台备份、检查旧规则与计量连续性，先更新面板并验收，再判断是否需要节点维护；HL 面板仍放在最后。

已知待补：IPv6-only 新节点目前仍需显式传入 `--node-address`；自动公网发现仍以 IPv4 为主。完整 Linux 新装/更新矩阵、跨网络转发、iPhone / Shadowrocket / v2rayN 实机结果在本次本地准备中不标记为通过。
