# v0.1.149：管理修改免下发、节点定向编译与持久化优化

规则管理作为设备组唯一业务标准，各节点从同一规则生成自己的执行配置。节点成员变化不改变无关成员的业务规则，不应因此让整个设备组重新编译或重新应用内核配置。

规则现在分别维护管理修订和运行修订。名称、备注、分类，以及未跨越耗尽状态的流量额度修改，继续更新管理修订、审计和幂等记录，供管理并发校验及 HT 完整配置同步使用；它们不改变执行片段、配置代数、部署回执或协议健康证明，也不通知节点应用。实际运行参数、私密上游凭据或流量额度耗尽状态改变时，才推进运行修订并走正常下发及回执校验。

旧快照未设置运行修订时，继续使用原有规则修订，因此迁移不会仅因新增字段而给全部节点重新编译。运行修订由存储层分配，不能由导入或用户请求指定。快照格式由 25 升为 26；旧程序不识别格式 26，需要回滚时必须同时恢复升级前的数据备份，不能只替换旧二进制。

删除已退役的节点时，历史 VLESS 运行材料仍可能要求节点属于当前设备组。删除接口返回成功后，下一次读取整份持久化状态失败，登录、心跳及多个管理接口随之报错。

本版本分开历史材料完整性与当前节点使用资格检查。退役、移组或删除不再单凭成员关系使历史快照不可读；删除或退役的节点仍不能读取秘密或取得新的运行材料。身份、规则、端点池、UUID、Reality 密钥及原生配置的完整性检查继续执行。

已消费的监控注册令牌按历史节点引用恢复，不再永久占用当前监控绑定。退役成员的上游凭据轮换不会重新激活它，退役首次编译失败恢复完整成员变更。

重新注册现在复用正常入组的原生 VLESS 材料补齐步骤。目标节点已有材料继续保留，显式撤销的材料不会复活；同组活动来源优先，无活动来源时，仅从通过完整性校验的未撤销历史材料为新节点补齐。旧节点不会因此重新取得成员资格或秘密读取权。来源损坏或存在歧义时拒绝操作并回滚。

成员入组、退役、删除及重新注册改为定向编译：只处理变更节点，以及引用受影响出口组的 QUIC/KCP 入口，撤下旧出口地址。无关存活成员不参与编译，配置、配置代数、运行材料及通知保持不变。权重和 priority 只改变新连接的调度投影，不生成内核配置。

所有相关成员和配置在变更前统一捕获，依赖编译失败时逆序完整恢复；成功后才消费注册令牌。批量编译全部成功后才通知发生配置变化的节点，后段失败不会提前发送通知。配置内容未变的节点复用原代数。

数据库在提交快照前完成一次恢复校验；不合法的成功领域操作回滚当前事务，保留上一次可读状态。相同密钥对的纯计算仅在单次校验内合并，不缓存权限。

同实例的快照写请求在借用数据库连接前排队，等待可取消，读请求保留自己的连接通道，避免多个写请求同时恢复即将过期的整份状态。提交前恢复校验产生的独立状态仅在 COMMIT 成功后保留，下一次写单次取用；它不复用业务回调修改过的对象。数据库行锁和格式版本、revision、xmin 三项复核继续执行，外部更新或同 revision 数据修复均强制重读，失败状态不会进入下一请求。健康续期仍在取得行锁后合并最新 overlay，不会借复用状态覆盖其他写入，也不因锁后复核重放业务回调。

新增脱敏事务诊断，覆盖主要快照读写及健康续期路径。失败日志包含固定阶段、取消或超时类别、SQLSTATE、提交结果、路由模式及耗时，不记录原始数据库错误、快照、请求正文、令牌或实际路径参数。COMMIT 确认失败标记为结果未确认，禁止据此自动重放；正常业务拒绝保持原有 HTTP 状态与消息，损坏持久化数据不再被误判为客户验证失败。

回归测试覆盖双节点退役后删除、存活节点配置及订阅身份保持、删除和重新注册的幂等重放、历史监控令牌、空组换机补齐、撤权不复活、QUIC/KCP 旧地址撤下、重叠依赖回滚、无关节点不编译或通知、权重及 priority 调整不编译，以及批量后段失败不提前通知。数据库测试覆盖真正 COMMIT 失败后不发布缓存或节点通知、使用同一令牌重试和重新打开数据库。
