# v0.1.191 — 收紧握手候选，保留实测可用备用

修复已知握手失败的域名仍被自动分配的问题。新建规则的自动 SNI 保留 Apple、iCloud、Amazon；Wikipedia、Microsoft、Cloudflare、Bing 不再参与自动分配，旧版面板返回它们时前端也会过滤。已有客户的端口、账号、密钥、SNI 和出口不会被批量改写。

节点内部候选收紧到七个：Apple、iCloud、Amazon、Google 下载站、Debian、Docker、Hetzner。美国与香港节点已逐项验证其中的实际 SNI / 目标组合；每台节点仍需用原 SNI 完成两次真实 Reality 认证和数据回传，成功后才可选用。一次地区性成功不代表所有节点都可用；所有候选失败时保留现有配置。

候选自身的域名不能因为内部转接成功就作为新 SNI 自动加入。客户端入口 SNI 与节点内部目标是两条不同的链路，只换内部目标无法修复某个客户网络拦截 SNI 的问题；这类旧规则需要针对性修复，并刷新原订阅。

后台探测继续按相同配置共享，保存和下发不等待远程检测。候选收紧减少每轮重复失败的握手工作量；不增加探测并发、不改变现有连接归属、不重载 Xray。界面将检测成功明确显示为“面板 → 目标 TLS 通过”。

使用本地保护构建并直接上传公开发行包，不调用付费 GitHub 构建，不升级 Xray 或 GOST。面板升级短暂中断管理请求；Agent 升级时该节点连接可能需要重连。具体部署范围、备份、回滚和公网验收以该轮执行报告为准。
