## 2. 参考系统的真实操作顺序

### 2.1 添加节点并使其上线

管理员添加节点，填写名称、服务器 IP、客户入口 IP、允许分配的起始/结束端口；添加后可复制安装命令，在对应机器执行后等待上线。节点卡片显示连接状态、CPU、内存、运行时长、上下行累计和速度。节点可编辑、删除；被隧道引用的节点不能直接删除。

这里“服务器 IP”和“入口 IP”分开很有价值：控制通信地址、节点间通信地址、客户接入地址不总是同一个。不能把用户已说明的国内三网入口和香港出口混成一个 IP 字段。

源码证据：

- `vite-frontend/src/pages/node.tsx:125` 初始化实时状态，`:163` 处理状态与指标；`:471` 获取安装命令；`:841` 节点表单。
- `springboot-backend/src/main/java/com/admin/service/impl/NodeServiceImpl.java:90` 创建；`:110` 列表隐藏密钥；`:123` 编辑并关联更新隧道 IP；`:191` 删除前检查引用；`:342` 生成安装命令。
- `gost.sql:55` 节点表包括 `server_ip`、`ip`、`port_sta`、`port_end`、`version` 和协议能力字段。

新项目应借鉴的用户动作：新建节点后直接显示“复制安装命令 → 等待连接 → 能力检测 → 可加入设备组”。不能只生成一枚注册令牌后要求用户自行猜测安装步骤。安装命令属于有权限才能获取的敏感内容，不能出现在普通列表或日志中。

### 2.2 建线路/隧道，再供用户选择

Flux 隧道分为端口转发与隧道转发。前者使用一台机器直接到目标；后者配置入口、出口及节点间传输。管理员还设置流量计费方式、倍率、监听地址和出口网卡。创建校验入口/出口存在并在线，隧道模式禁止入口出口为同一节点。列表可编辑、诊断、删除；删除前检查转发与用户授权引用。

源码证据：

- `vite-frontend/src/pages/tunnel.tsx:151` 表单校验；`:190` 新增默认值；`:209` 编辑；`:295` 诊断；`:626` 名称/类型/流量计费表单；`:775` 出口配置。
- `springboot-backend/src/main/java/com/admin/service/impl/TunnelServiceImpl.java:110` 创建；`:165` 编辑；`:232` 删除；`:492` 使用关系检查；`:635` 分段诊断。
- `gost.sql:110` 隧道表含入口/出口节点、入口/出口 IP、类型、传输协议、流量倍率、监听地址和出口网卡。

新项目应保留 NY 更强的入口组、出口组与中继组织能力，不能退化成 Flux 的单入口/单出口模型。界面应让用户先选择“直入直出 / 入口经出口 / SOCKS5 落地”，再展示相应字段。客户接入协议另选 TCP/UDP/SOCKS5/VLESS，不能把 VLESS 和“出口”混在同一组选项里。

### 2.3 用户总额度与每条线路授权分开

Flux 用户有用户名、密码、总流量、总转发数量、重置日、到期时间、状态。进入某用户的隧道授权窗口，可分配线路并设置该线路的流量、数量、限速规则、重置日和到期时间。用户总额度和线路额度分别显示，也分别重置。普通用户创建转发只能选择自己被授权的线路。

- `vite-frontend/src/pages/user.tsx:335` 管理隧道权限；`:349` 分配；`:396` 修改；`:453` 重置账号流量；`:484` 重置线路流量；`:760` 用户表单；`:883` 授权表单。
- `springboot-backend/src/main/java/com/admin/service/impl/UserTunnelServiceImpl.java:84` 防止重复授权；`:159` 更新额度/限制，并在限速变更后更新现有转发；`:404` 更新该用户线路下全部转发限速。
- `springboot-backend/src/main/java/com/admin/service/impl/ForwardServiceImpl.java:782` 到期/授权检查；`:828` 用户总数量与该线路数量检查；`:855` 恢复前检查已用流量。

新项目最优先缺的就是这类业务对象与真实权限。管理员账号不是客户账号；节点注册令牌也不是客户凭据。不能拿管理员登录功能替代“用户管理完成”。

### 2.4 开通转发、复制地址并日常维护

Flux 新建转发选择隧道、名称、入口端口、目标地址，入口端口可自动分配。多目标时选择主备、轮询、随机、IP 哈希。管理员列表按用户和隧道分组；普通用户只看到自己的转发。每条可编辑、暂停/恢复、删除、诊断、复制地址；还支持排序、按隧道导入和导出。

新项目规则页应覆盖以上日常操作，但设备组选择只填一次。用户选择 10 台机器组成的组后，只得到一个稳定接入地址或一条 VLESS URI；不能导出 10 条机器 URI。组内机器的权重、启用/停用、排空和故障摘除由服务端处理，每次新连接选一个合格成员。

### 2.5 流量与限速要真实影响转发

Flux 有独立限速模板，绑定隧道并供用户授权使用。节点上报流量后，计入转发、用户与用户线路授权三个层次，再根据额度、到期和禁用状态暂停服务。月度重置日支持 0=不重置、1–31=对应日，小月末处理超出天数。仪表盘还查询近 24 小时流量。

## 3. 数据关系及建议的产品入口

| 业务对象 | Flux 关联 | 新项目用户可见入口 | 必须交付的结果 |
|---|---|---|---|
| 节点 | 隧道引用入口/出口节点 | 节点管理 | 可安装、上线、检测、编辑；引用清晰 |
| 设备组 | 此参考版本无等价模型 | 入口组/出口组 | 添加已有节点，配置权重与状态；成员只维护一次 |
| 线路/隧道 | 节点 → 隧道 → 转发/授权 | 线路管理 | 可选入口组、出口方式、传输和计费；分段诊断 |
| 客户 | 用户 → 授权/转发/统计 | 用户管理 | 独立账号、额度、到期、状态、归属规则 |
| 用户线路权限 | 用户 + 隧道 + 限速 | 用户详情的线路授权 | 仅授权线路可用；总额度与线路额度分别生效 |
| 规则/服务 | 所属用户 + 隧道 + 目标 | 转发管理 | 开通后复制可用地址；编辑、启停、删除、诊断 |
| 限速 | 模板 → 用户线路授权 | 限速管理 | 单位明确；变更对现有规则生效 |
| 导入批次 | Flux 前端逐条调用创建 | 导入迁移 | 先预检，再映射，再提交；逐条结果可追踪 |
| 客户订阅 | 此参考版本不足以证明完整契约 | 服务详情/用户交付 | 一条稳定链接；可撤销/轮换；不泄露其他客户 |

完整导航建议：总览、转发管理、入口组、出口组、线路/隧道、节点、用户、流量与限速、导入迁移、操作记录/系统设置。具体 NY 页面命名应以授权只读核对结果为准，不能用该导航建议宣称已经恢复 NY 全量菜单。

## 4. 优先实现次序与用户验收

### P0：用户能实际开出一条规则

1. 节点页添加隔离测试节点，复制安装命令，安装后页面显示真实在线与能力，错误令牌被拒绝。
2. 创建入口设备组，加入两台已登记测试节点。调整权重和停用状态后，详情、配置与候选机器保持一致。
3. 创建用户并指定额度、到期和规则数量，授权一条线路。未授权用户访问接口也不能创建或读取该线路的规则。
4. 转发管理创建最基础 TCP/SOCKS5 业务并复制地址；真实客户端穿过新测试节点到自有测试目标成功。再补 VLESS，不能以新增 VLESS 为由缺失原本转发业务。
5. 修改目标、暂停、恢复、删除分别验证真实连接结果，页面显示“提交中/已应用/失败”，不能收到控制面 HTTP 200 就显示“已生效”。

### P1：用户能维护额度与批量迁移

1. 额度耗尽或到期会停止该客户服务，其他客户继续工作；扩容/续期后可明确恢复。
2. 修改限速影响现有规则；查看用户、线路、规则流量能解释相互关系与倍率。
3. 导入混合有效/错误/重复行先预检，用户可看见将新增/跳过/冲突的数据和引用映射；提交后逐条结果准确，重试不会重复创建。
4. 批量启停/迁移给出影响数量与每条结果。Flux 此版本只明确看到批量导入/导出与关联配置更新，没有据此确认通用批量启停/删除。
5. 节点或线路删除前列出引用；节点暂时离线时不得假装已经清除远端服务。

### P2：用户例子的单链接多机器 VLESS 交付

1. 同一个客户、同一条稳定 VLESS URI，使用 2 台隔离机器验证轮询/权重与故障摘除，再扩到 10 台。
2. 组内减少一台后新连接走剩余机器，客户端 URI 不变；已有落到故障节点的连接会断开，需要重连，这一点必须如实展示。
3. DIRECT 与 SOCKS5 落地分别验证：接入协议始终是 VLESS，出站路径是独立配置。
4. 单入口网关本身的故障不能冒充“全链路高可用已完成”；必须另有网关冗余验收。

每个阶段同时验收宽屏、窄桌面和手机布局，覆盖列表、空状态、表单错误、加载、保存失败、操作完成、刷新后状态、越权 API、浏览器控制台。只加菜单和占位页不算完成。

## 5. 只借鉴产品能力，不复制参考实现的问题

- Flux `ForwardServiceImpl.java:306` 的强制删除会跳过 GOST 清理，仅删除数据库行。新项目应保留可重试的删除任务与审计，不默认提供“消失了就算删除成功”的体验。
- `UserTunnelServiceImpl.java:130` 移除授权时捕获转发清理异常后仍删除授权；`UserServiceImpl.java:539` 用户删除也存在记录错误后继续删除记录的路径。新平台必须能追踪远端尚未撤销的残留。
- `ForwardServiceImpl.java:828` 编辑数量检查对总数量与线路数量的排除方式不完全一致；新实现应测试“已达配额时编辑现有规则”仍允许合法编辑。
- `FlowController.java:302` 遍历多个转发时复用传入服务名，说明“暂停了所有记录”与“实际暂停所有数据面服务”不能仅凭源码注释推断，应逐条验证。
- `forward.tsx:878` 是浏览器逐条提交导入，最终提示“执行完成”不等于全部成功。新平台应有服务端批次、幂等键和可恢复结果。
- `node.tsx:135` 参考实现将 token 放在 WebSocket URL 查询参数；新项目不应复制这种易进入访问日志的凭据传递方式。
- 当前 Flux 引擎与页面本身没有替代 NY 私有协议的证明；本项目只能以公开引擎实现经过测试的等价业务能力。
