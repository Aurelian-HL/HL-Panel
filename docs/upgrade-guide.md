# 面板与节点更新指南

[返回 README](../README.md#面板与节点更新) · [安装与运维](../deploy/README.md) · [节点稳定性维护](node-maintenance.md)

## 先判断机器角色

**更新脚本只作用于当前 SSH 登录的机器，不会根据面板里的节点列表自动去更新其他服务器。**

| 你要做什么 | 登录哪台机器 | 使用哪个入口 | 需要注册令牌吗 |
| --- | --- | --- | --- |
| 全新安装面板 | 准备作为管理端的全新 VPS | `install.sh` | 不需要 |
| 更新已有面板 | 当前面板服务器 | `update.sh` 或面板网页的“版本”弹窗 | 不需要 |
| 安装新节点 | 要加入设备组的节点服务器 | 面板生成的 `install-node.sh` 完整命令 | 需要 |
| 更新已有节点 | 当前节点服务器，每台分别执行 | `update-node.sh` | **不需要** |
| 已有节点重装或换组 | 原节点服务器 | 目标组生成的新安装命令 | 需要新令牌 |

不确定登录的是哪台机器时，先检查 SSH 目标，再执行以下只读命令：

```sh
hostname
systemctl list-unit-files hl-panel-control-api.service hl-panel-edge-agent.service --no-pager
```

`hl-panel-control-api.service` 是面板服务；`hl-panel-edge-agent.service` 是节点服务。`/opt/hl-panel` 这个目录名两种角色都会使用，**不能仅根据目录存在就判断机器角色**。两种服务均存在时，表示本机可能兼任两种角色，需要分别维护；两种都没有时，先核实安装方式，不要盲目执行更新。

## 更新前准备

1. 查看[正式发布说明](https://github.com/Aurelian-HL/HL-Panel/releases)，记录面板与各节点当前版本及目标版本。
2. 确认目标服务器能访问 GitHub API、Raw 和 Release 下载地址。节点还必须能通过可信 HTTPS 访问所属面板。
3. 安排维护窗口，确认磁盘有空间保存安装包、程序和数据库备份。不要删除身份文件、账本或旧备份以“修复”更新。
4. 面板先导出加密业务备份并妥善保管；更新器还会生成本机恢复备份。备份操作见[备份与恢复](../deploy/backup-and-restore.md)。
5. 先面板，后节点。节点逐台更新，每台通过真实转发验收后再继续，避免整组同时中断。

以下操作面向官方标准安装。自定义目录、数据库或服务配置的实例应先核对兼容性，不要通过改文件权限或删除配置绕过更新器检查。

## 一：面板服务器保数据更新

**只在已安装网页管理端的面板服务器，以 root 执行：**

```sh
curl -fsSL https://raw.githubusercontent.com/Aurelian-HL/HL-Panel/main/update.sh | bash
```

它更新控制 API、管理端与所需数据库结构，保留账号密码、用户、规则、设备组、节点身份记录、订阅、限额、流量账本、域名及证书。下载校验期间面板继续运行；切换时短暂停止面板并备份本机 PostgreSQL，升级后检查服务与实际版本。

**它不会 SSH 到节点，不会更新远端 Agent、Xray 或 GOST。** 节点通常继续运行最后有效规则，面板 API 和在线订阅下载会在切换期间短暂不可用；不要把这一点当作所有业务绝对无中断的保证。

### 网页更新与指定版本

网页入口：**首页 → HL-Panel 运行状态 → 版本 → 刷新版本列表 → 选择较新的正式版本 → 输入当前管理员密码 → 确认保数据更新**。任务开始后关闭弹窗不会取消后台更新；服务切换时网页可能重连，恢复后核对实际版本。

旧安装缺少网页更新服务时，先执行上述终端命令。已有本机更新工具也支持：

```sh
# 仅检查面板版本，不执行升级；仍可能查询 GitHub
hl-panel-update --check
```

需要指定版本时，将 `vX.Y.Z` 换成真实存在的正式版本：

```sh
curl -fsSL https://raw.githubusercontent.com/Aurelian-HL/HL-Panel/main/update.sh | bash -s -- --version vX.Y.Z
```

面板更新只接受正式 Release，拒绝降级；回退应使用对应备份中的恢复工具。自动数据库处理仅支持标准安装器创建的本机 PostgreSQL，不支持自行改成远程数据库的实例。

### 面板更新后检查

```sh
systemctl status hl-panel-control-api.service --no-pager
journalctl -u hl-panel-control-api.service -n 50 --no-pager
```

然后登录网页核对当前版本、账号、规则、设备组、订阅和节点状态。只有这一步完成，才开始更新节点。分享日志前请脱敏。

## 二：节点服务器保身份更新

**SSH 登录要升级的那一台节点服务器，以 root 执行。不要在面板服务器执行：**

```sh
curl -fsSL https://raw.githubusercontent.com/Aurelian-HL/HL-Panel/main/update-node.sh | bash
```

默认读取本节点配置中的面板地址，通过公开版本接口核实面板当前正式版本，再下载该标签的更新器和发布包。面板未更新时，节点不会因为 GitHub 出了新版本就自动跳到新版；面板 HTTPS 或版本接口不可达时，先修复连接，不要反复重装。

更新内容是本机 Agent（包含探针）、Xray 与 GOST。更新器保留注册凭据、配置、流量账本和最后有效规则，**不需要新令牌，不改变设备组**。不要把目标组的新安装命令当作常规更新命令：那是重新注册 / 换组流程。

需要固定版本时，将占位版本替换为与所属面板兼容的正式版本；通常使用默认跟随方式即可：

```sh
curl -fsSL https://raw.githubusercontent.com/Aurelian-HL/HL-Panel/main/update-node.sh | bash -s -- --version vX.Y.Z
```

切换程序时会停止并重新启动本节点服务，连接需要重连。下载期间仍保留现有服务；不要同时升级整个入口组。

### 每台节点更新后检查

```sh
systemctl status hl-panel-edge-agent.service --no-pager
journalctl -u hl-panel-edge-agent.service -n 50 --no-pager
```

回面板核对该节点的身份、组归属、Agent 版本、最近采样与规则应用回执；在真实客户端刷新订阅、连接并传输数据。仅有 `active` 或心跳正常不能证明业务路径正常。确认本节点通过后，再登录下一台节点重复本节操作。

## 误执行了另一种更新命令

| 发生了什么 | 如何处理 |
| --- | --- |
| 在纯面板服务器执行 `update-node.sh` | 默认入口读取安全的节点配置，底层更新器还会核对受管节点身份。没有节点配置 / 身份时会拒绝继续。保留错误提示，确认面板服务状态，再使用面板 `update.sh`；不要安装 Agent 或伪造身份文件来绕过错误。 |
| 在纯节点服务器执行 `update.sh` | 面板更新器要求受管 `current` 发布目录、面板配置及数据库。检查不满足会拒绝继续。保留日志，确认 Agent 状态，然后使用节点 `update-node.sh`；不要初始化数据库或运行全新安装来“补齐”条件。 |
| 同一台机器兼任两种角色 | 两套配置都可能有效，脚本不能替你判断意图。分别确认要维护的服务；执行节点更新仍可能中断该机转发，执行面板更新仍需数据库备份。 |
| 已经切换过程序或服务异常 | 先检查实际服务与日志，保留本次备份；根据更新器输出的准确回滚命令处理，不要靠重复执行两种命令尝试恢复。 |

误执行后不要直接假定“没有影响”。确认有没有受管配置、更新是否进入切换阶段，以及真实服务与数据是否正常。

## 失败与回滚

| 更新对象 | 本机备份根目录 | 恢复注意事项 |
| --- | --- | --- |
| 面板 | `/var/backups/hl-panel/` | 使用本次备份目录中的 `rollback.sh`，恢复程序与数据库；数据库回到备份时刻，需先另存升级后的新增数据 |
| 节点 | `/var/backups/hl-panel-node/` | 使用本次备份目录中的 `rollback.sh`，恢复旧程序及本次受管服务变更；保留节点身份、状态及账本 |

更新器在切换阶段失败会尝试自动恢复；**是否恢复成功以终端输出、服务状态和实际业务为准**。下载或前置校验失败时，不要执行不相关的旧备份恢复。请保存更新器输出的准确备份路径与回滚命令，不要把示例路径当作真实备份执行。

不要只切回旧面板程序、继续使用新结构数据库，也不要删除节点状态目录重新注册来代替回滚。面板回滚后重新核对各节点版本及兼容性。恢复细节见[备份与恢复](../deploy/backup-and-restore.md#回滚)。

## 版本检查与维护规则

正式 Release 才是可安装版本，main 分支提交、README 编辑、草稿与预发布不计入正式版本差。安装 / 更新入口按标签获取配套脚本与包并校验摘要，不覆盖已发布标签。

| 落后正式版本数 | 面板提醒 |
| --- | --- |
| 0 | 显示已同步 |
| 1～2 | 可以选择“下次更新”，同一个新版本暂缓 24 小时 |
| 3 个及以上 | 持续提醒，并提供 GitHub 和保数据更新入口 |
| GitHub 查询失败 | 显示尚未核实，可重试；不误报已是最新 |

版本列表最多读取最近 100 个正式发布，自动检查缓存 15 分钟；手动刷新可提前查询，两次 GitHub 查询至少间隔 1 分钟。检查本身不会自动重装或锁死业务。

反馈更新问题时，请附面板与节点版本、当前机器角色、脚本名、失败阶段，以及脱敏后的终端输出。维护安装 / 更新行为时，需同时更新 [README](../README.md)、本指南及相关运维说明，再经过发布检查发布新的正式版本。
