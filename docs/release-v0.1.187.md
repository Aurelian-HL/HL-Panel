# v0.1.187 — 下发队列恢复与计量连续性

修复“节点在线，规则已经保存，却一直停在下发中”的一种根因：配置编译版本落后时，心跳会安排重新编译；旧实现把排队成功误当成编译完成，清掉重试冷却，后续心跳不断作废正在编译的任务。

## 本版变更

- **保留编译重试冷却。** 心跳提交后给已排队的编译留出执行时间，不再每次心跳都作废任务、重置恢复次数。
- **保留真实变更的同步。** 规则增删改、能力变化仍按既有流程入队；失败重试、过期租约及防止旧任务覆盖新配置的校验继续生效。
- **保留既有监听。** 节点在新配置发布前继续使用已确认配置，不靠重启引擎、删除规则或伪造下发回执解决排队。
- **继承此前计量修复。** 采样与发送分开执行，积压按最多 128 条连续补报，已确认报告才出队；重复报告不重复累计。
- **继承订阅来源恢复。** 保留原身份，明确无效来源，不把同端口新规则自动绑定给旧订阅。

## 已验证与待验收

隔离 PostgreSQL 测试覆盖持续心跳期间的任务版本、重试次数和发布结果；另以 512 条已有规则为基线新增第 513 条客户规则，完整配置成功生成，原有 512 条监听配置未变。将关键函数回退到旧实现后，相同测试会重现新客户规则持续排队。

本地编译与数据库验证不等于公网下发时延，也不等于生产恢复。正式包仍需完整 CI；升级后分别核对配置回执、业务端口、订阅、实际转发，以及至少两个采样周期内的计量进度和旧积压确认。

## 发布与升级

v0.1.185、v0.1.186 构建已取消，未公开发布、未部署。本版使用独立版本号重新构建，不覆盖旧标签。

按 QWE、AAA1、HL 顺序，先面板、后所属节点，逐台验收；HL 最后。保留必要备份和回滚方法，保持客户累计、旧流量队列及原订阅身份。Xray / GOST 核心不升级。

Agent 维护可能短暂中断被操作节点的连接，客户端需要重连。真实网络或上游故障需另行处理，不能以空订阅、清空计量或假回执掩盖。
