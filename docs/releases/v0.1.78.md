# v0.1.78 — 规则流量持久汇总与增量写入

流量核算改为持久汇总，普通用量增长改为独立记录，减少历史账本扫描和整份业务快照的编码、写入及缓存失效。

## 修改

- 新增规则累计及 UTC 月度用量汇总。首次升级在事务内回填历史账本，并安装按语句维护的触发器；事件写入、重试去重与汇总更新在同一事务内完成。
- 累计额度和完整 UTC 月额度按主键读取汇总；任意时间区间仍按原始账本精确查询。数据库异常和数值溢出继续报错，不能当作零用量。
- 未跨额度、未换月份的规则用量只更新独立记录，不再改写整份快照。跨额度、月清及业务编辑继续使用原有事务、审计和配置编译机制。
- 跨实例及进程重启读取最新用量。并发投影保持高水位；迟到的旧规则版本、旧月份不会覆盖当前状态。
- 迁移导出合并最新用量；导入清除目标机旧投影，再恢复来源状态。汇总表属于派生数据，由恢复账本的事务重新维护。

## 验证与边界

隔离 PostgreSQL 测试覆盖并发计数、事务回滚、历史升级回填、重试、UTC 月边界、批量更新/删除/清空、触发器失效检查、汇总读取不访问账本、数值溢出、进程重启、跨实例、额度暂停及迁移恢复。

这是高频流量路径的拆分，其他业务状态仍使用集中式快照。不会减少采集频率、放宽协议健康判断或停用额度核算来降低 CPU。线上效果应在相同采样方法下观察正常业务负载，短时数据不能代表长期峰值。

## 更新与回滚

仅在面板服务器运行 README 的**面板保数据更新命令**；本次流量存储优化不要求升级节点端。首次升级需要一次历史回填，账本越大耗时越长。更新器会在切换前备份数据库、配置及程序，并生成回滚脚本。

旧版程序不认识独立用量投影，不能只替换旧二进制回退。升级期间失败应使用更新器的完整恢复流程。业务恢复后若需要降级，须先保存当前完整数据库及迁移备份、安排维护并确认恢复点；升级前备份不包含升级后新增业务，不能直接覆盖正在运行的数据库。
