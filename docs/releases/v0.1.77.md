# v0.1.77 — 流量核算读取优化

节点流量上报和额度同步不再为查询客户、规则额度或配置凭据反复解码整份业务快照。新增独立的只读数据视图，只保留核算所需字段；共享数据与调用者隔离，写入提交后才发布。

## 修改

- 规则额度读取绕过完整部署状态计算。
- PostgreSQL 额度核算只查询计费字节总量，跳过事件数量、分页明细和处罚记录查询。
- 每次读取仍核对数据库版本与行标识，支持其他实例更新及同版本数据修复；数据库错误不会返回旧缓存或零额度。
- 迟到流量继续在请求事务中读取归档配置及生效凭据。重试去重、月清边界、额度暂停和配置失败回退语义保持一致。

## 验证

- 全量 Go 测试及 `go vet ./...`。
- 流量、内存仓库、PostgreSQL 快照、协议健康调度的竞态测试。
- 隔离 PostgreSQL 测试覆盖缓存隔离、跨实例更新、提交失败、归档配置及月度时间边界。
- 管理端 268 项和用户端 27 项测试、类型检查及生产构建。

## 性能边界

本次优化减少重复读取和不必要查询；没有迁移数据库结构。业务变更仍会重写集中式快照，计费总量仍由历史账本 SUM 得出。规则和上报量较大时，下一阶段需采用持久化规则汇总及按业务域拆分存储，保留事务、重试去重和月清约束。

本地基准仅衡量查询及解码成本，不代表线上整机 CPU 降幅。真实效果应在更新后的正常业务负载下采样比较，不能通过降低协议健康要求或停用额度核算换取性能。

## 更新

仅在面板服务器运行 README 中的**面板保数据更新命令**。本次修改不要求更新节点端；不要在面板服务器执行节点更新命令。更新前由项目更新器保存数据库、配置和旧程序，并生成回滚脚本。
