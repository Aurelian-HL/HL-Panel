# v0.1.185 — 订阅连续性、流量同步与来源恢复

修复周期健康证明过期导致的订阅不可用、新规则流量被积压报告拖住，以及历史订阅来源已删除却仍显示可恢复的问题。

## 主要变化

- **已部署规则持续可用。** 取消周期协议健康证明的时效门槛，按真实配置应用回执判断部署状态。暂停、配额、零权重、退役和身份校验仍生效。
- **新流量持续采样。** 将节点采样与网络上报拆开；旧报告重试不再阻塞新计数采集。批量接口最多接收 128 条，仅确认真实提交的连续前缀，重放不重复计费。旧面板自动退回单条接口。
- **历史订阅明确显示原因。** 原规则、凭据或入口已删除时，列表和详情显示具体原因；禁止没有有效来源的恢复、导入包和二维码操作。
- **保留原订阅身份。** 不删除历史数据、不重发 token，也不把同名或同端口的新规则绑定到旧订阅。原身份完整恢复后可继续使用；多线路订阅仍可保留有效线路。
- **时间跨度回归。** 覆盖部署后 2 分钟、1 天、7 天，避免只验证刚建好的规则。HTTP/2 故障连接恢复仍使用短请求超时；仅将测试的首次 TLS 建连预算与恢复断言分开，生产参数未改变。

## 更新方法与边界

先更新面板，再逐台更新 Agent，分批检查心跳、配置回执、流量补报和真实转发。只更新面板不能启用节点独立采样及快速补报。升级保留原数据与计量队列，保留可用回滚路径。

Xray / GOST 核心版本不变。独立部署的 connection-gateway 需要更新对应程序才能取消其旧证明期限限制。节点 Agent 维护可能短暂中断该节点连接；现有 TCP 连接不会迁移到其他机器，客户端需重连。

真实网络或上游认证故障仍需单独修复。订阅接口不返回空白成功内容来掩盖故障；本次代码修复不能保证无法到达上游的节点恢复网络。生产升级结果与原设备验收以实际记录为准。

源码与历史保存在私有仓库，公开仓库仅包含交付文件和正式二进制包。
