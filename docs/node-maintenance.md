# 节点稳定性维护

节点维护以本仓库的代码、回归测试和正式 Release 为准。单机临时处理发现的通用问题，需要回到仓库修复；不要把 SSH 密码、节点凭据、用户 UUID、订阅地址或 Reality 私钥提交到仓库或工单。

## 已纳入维护的故障

| 故障 | 修复与验收 | 首个版本 |
| --- | --- | --- |
| 引擎退出通知被一个观察者消费，其他观察者仍认为进程存活 | 退出通过关闭 channel 广播；真实 Xray 退出后，多次状态检查均判为停止 | v0.1.72 |
| 已应用配置后没有新 generation，运行中引擎退出无法自行恢复 | 独立本地恢复循环使用最近验证成功的配置；正常检查间隔 5 秒，失败按配置退避 | v0.1.73 |
| 控制面不可用时，引擎恢复先等待网络报告 | 本地恢复先启动、验证和保存终态回执；联网后同步循环补报 | v0.1.73 |
| 主动停止被自动恢复或新配置覆盖，Agent 重启后再次启动 | 停止意图单独持久化；停止、应用和恢复共用生命周期锁，只有主动重启解除停止 | v0.1.73 |
| 显式重启前未保存最后一段可读流量计数 | 重启前采集到本地账本；账本持久化失败拒绝重启，计数端点不可读时允许修复并记录告警 | v0.1.73 |
| Xray 忽略自定义统计 API 地址，监听与采集地址不一致 | 编译、配置校验、激活与回滚统一使用配置中的 loopback 地址；拒绝公网监听及非法端口，真实转发后查询计数 | v0.1.73 |
| 仅修改另一引擎或配置元数据，也重启未变化引擎并断开已有连接 | 对比验证后的原生配置、受管存活进程摘要及磁盘配置；真实双引擎测试保留同一 TCP 连接，连续更新和回滚另一引擎 | 未发布 |
| 无效回滚先终止健康进程 | 停进程前验证回滚配置；相同原生配置保留存活进程及计数代数 | 未发布 |
| 流量采集窗口跨越配置提交，归入错误代数 | 采集与引擎配置提交共用锁，网络投递保留在锁外；阻塞提交回归验证采样归属 | 未发布 |
| 主动探测摘除被短暂拨号冷却到期、并发拨号成功或租约续期清除 | 主动探测否决与拨号冷却分离；连续成功探测达到阈值才解除主动否决，拒绝旧快照结果 | 未发布 |

恢复仅适用于 Agent 管理的 Xray / GOST 进程。空配置不会周期性拉起引擎。正常存活的进程不会因例行检查重启。5 秒是检查间隔，实际恢复耗时还包括生命周期锁等待、配置校验和进程启动；失败时采用退避，不能保证所有故障都在 5 秒内恢复。

该机制修复进程退出后的恢复，不能代替出口质量判断、DNS 健康路由或完整用户路径检测。心跳在线、TCP 端口可连接和真实协议转发成功是不同状态。现有连接因进程退出或升级断开后，需要客户端重连。

## 排查顺序

1. 记录发生时间、时区、线路、客户端和是否同时影响多个用户。分别确认订阅下载失败还是已导入的节点连接失败。
2. 面板检查节点 Agent 版本、引擎版本、心跳、desired/applied generation、应用回执和协议健康租约。应用成功记录不能单独证明当前进程仍运行。
3. 节点只读检查 Agent 与受管引擎、监听端口、重启次数、资源、时间同步和内核错误。以下命令不改变服务：

   ```bash
   systemctl show hl-panel-edge-agent.service \
     -p ActiveState -p SubState -p MainPID -p NRestarts -p MemoryCurrent -p TasksCurrent
   ps -C edge-agent,xray,gost -o pid,ppid,comm,rss,etimes
   ss -lntp
   timedatectl show -p NTP -p NTPSynchronized
   journalctl -u hl-panel-edge-agent.service --since '30 minutes ago' --no-pager
   journalctl -k --since '30 minutes ago' --no-pager
   ```

   日志和端口输出仅供本机诊断，提交问题前脱敏。不要公开配置、数据库快照或订阅包。
4. 分段验证实际路径：入口协议握手、出口连接/认证、目标 HTTP/TLS 响应。TCP 成功不等于 SOCKS5 认证或 VLESS/Reality 可用；节点本机成功也不等于客户所在网络成功。
5. 若使用多个 DNS 地址，核对每个地址均对应当前有效成员。设备组调度无法控制客户端直接解析到的坏 DNS 地址，不得用心跳正常代替逐地址验收。
6. 检查证书链、有效期、客户端时间、IPv4/IPv6和实际网络；不要通过关闭 TLS 校验掩盖证书或时间问题。
7. 同一订阅仍可能解析到不同入口、走不同运营商路径。逐地址检查客户凭据、Reality 参数和实际出口一致性；在客户失败的同一时间对照入口与出口，不能用维护者网络正常判定客户线路正常。

完整的分段排查和回归清单见 [间歇性超时维护计划](maintenance/intermittent-timeout.md)。入口专用探测若转发到本机 echo，不代表客户 SOCKS5 出口可用；多 A 记录直连节点也不会自动经过网关的故障摘除逻辑。

## 发布与滚动升级

每次修复应包含复现、回归测试和发布说明。正式安装包必须从同一不可变标签生成，并通过校验与发布流水线；main 分支更新不等于现有实例升级。

先完成[面板服务器更新](upgrade-guide.md#一面板服务器保数据更新)，再 SSH 登录每一台目标节点，以 root 使用保身份更新，无需重新注册或提供令牌。**以下命令仅在节点服务器执行，不是在面板服务器执行：**

```bash
curl -fsSL https://raw.githubusercontent.com/Aurelian-HL/HL-Panel/main/update-node.sh | bash
```

不指定版本时，脚本读取当前面板正式版本，因此先核对面板版本。面板更新不会自动更新各节点。全新节点使用面板生成的安装命令；不要拿全新安装或换组重装代替保身份升级。

升级前核对节点身份与配置摘要、现有规则状态和本地账本。更新器下载、校验和准备恢复材料期间保留当前服务，切换时短暂停止本节点 Agent，升级失败自动恢复旧程序。身份、运行状态和流量账本留在原位置，不复制为长期归档。不要同时更新整组入口；先更新一台，确认版本、身份、配置、流量账本和真实协议转发后再更新下一台。切换会断开该节点已有连接。

更新、重装只在 `/opt/hl-panel/.node-update-*` 或 `.node-reinstall-*` 创建本次替换的私有临时目录。成功或成功恢复旧程序后清理；只有待验收或恢复未完成时保留恢复材料。首次从旧更新器升级时兼容旧临时路径 `/var/backups/hl-panel-node/update-*`，完成后也清理本次目录，不清除无关历史归档。恢复未完成的面板任务按[节点一键更新恢复流程](node-one-click-update-design-20261019.md#验收与恢复)处理；不要删除状态目录、重新注册节点或覆盖客户线路来尝试恢复。停止意图采用独立文件，兼容旧版 journal 解码；恢复到不支持该意图的旧版 Agent 后，需重新核对主动停止状态。

面板使用 README 中的保数据更新流程。面板回滚可能恢复备份时的数据，执行前另行保存新增数据。验收至少涵盖正式版本、业务身份/配置未变、公网订阅和真实规则路径。

## 持续维护清单

| 时机 | 必须处理的内容 | 判定标准 |
| --- | --- | --- |
| 每次发布 | 真实引擎集成测试、安装与保数据更新流水线 | 全部通过后发布；不把跳过的真实引擎测试算成功 |
| 节点升级后 | 版本、身份、账本、应用回执、协议路径 | 单台通过再继续；失败保留证据并使用对应回滚 |
| 超时再次发生 | 同时采集入口、出口、面板与客户时间窗口 | 区分进程、控制面、DNS、出口和客户网络，不仅检查端口 |
| 组成员或域名变化后 | 每个实际解析地址、有效成员和订阅入口 | 新旧地址变化与真实协议连接一致 |
| 后续迭代 | 持续协议探测、出口质量与资源趋势 | 在隔离环境确定阈值、误判处理和回归，再上线；未实现前不宣称具备自动 DNS 故障摘除 |

该清单是仓库维护流程，不会自行创建定时任务或自动改变生产 DNS。事件排查与发布结果应记录脱敏证据、未复现条件和未更新节点，避免把一次成功当作间歇故障已经消失。

## 回归测试

发布流水线下载固定版本真实引擎，只在 loopback 环境测试进程退出与恢复，不对生产注入故障：

```bash
NYVP_XRAY_BINARY=/absolute/path/to/xray \
NYVP_GOST_BINARY=/absolute/path/to/gost \
go test -race ./internal/agent/... ./tests/integration/xray ./tests/integration/gost
```

`internal/agent/runtime/engine_recovery_test.go` 覆盖无新配置、控制面不可用、真实转发、主动停止、新配置不能绕过停止、Agent 重启保留停止意图、主动重启及离线本地启动。`internal/agent/reconciler` 额外验证恢复不调用控制面、回执延迟投递、存活进程不重启和空配置不进入恢复循环。

`tests/integration/gost/mixed_stability_test.go` 通过真实 Xray 与 GOST 验证更新另一引擎及回滚时已有 TCP 会话持续传输、未变引擎计数代数稳定。该用例使用 loopback TCP 转发，不替代 VLESS/Reality 完整协议测试，也不代表线上间歇故障已解决。原生配置确有变化时仍会重启对应引擎，客户需要重连。
