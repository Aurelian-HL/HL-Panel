# NY 业务体系重构：纠偏与验收基线

日期：2026-10-02。由用户对 xzf 功能缺失的反馈触发。本文定义应交付内容，不是新增功能完成声明。

## 纠偏结论

原始目标一直是：保留 NY 的完整业务体系并支持 NY 导入，在此基础上增加 VLESS 等客户接入协议；设备组由管理员添加机器，客户只有一个稳定端点、一条协议链接，服务端按权重/轮询等策略选取健康成员。新面板独立运行，不依赖鸿乐运营后台。

当前 xzf 是第一阶段工程骨架。登录、持久化、HTTPS、空页面浏览器验收是真实结果，但不证明 NY 能力完整，也不证明用户可以开通线路。此前实施顺序将登录、设备组、端点和协议实验优先于用户日常转发流程，造成已上线产品与目标严重偏离。

本轮重新核对了 NY 官方说明、本地 Flux 源码、新平台实际代码，以及 zf 的三个只读业务接口。证据见：

- [现有 NY 只读记录](ny-live-reference-20261002.md)：当前账号可见 5 入口、3 出口、648 规则，真实用户和规则字段。
- [源码缺口](implementation-gap-20261002.md)：四个页面、无规则/客户域、订阅占位、Agent dry-run、网关脱离控制面。
- [NY 官方参考](ny-official-reference-20261002.md)：官方功能及边界。
- [Flux 操作流程参考](flux-workflow-reference-20261002.md)：从机器、隧道、授权到规则的可操作流程，不复制其代码或 React 技术栈。

## 应恢复的业务界面

菜单组织是新平台的建议，不声称复制了 NY 当前后台的全部实际菜单。按下列完整业务模块组织，而不是添加空菜单后宣称兼容：

| 模块 | 管理员能完成的动作 | 与当前四页的差异 |
| --- | --- | --- |
| 总览与监控 | 用户/规则/设备数、流量与容量、在线/离线、同步失败和待处理任务，统计口径清楚 | 当前只是节点/组计数 |
| 设备管理 | 添加机器、获取受控安装命令、安装状态、角色/能力、地址、版本、资源、升级与退役 | 当前只发注册令牌、列心跳 |
| 入口组、出口组、直出设备组 | 成员、入口域名/IP、端口池、允许的出口/用户、倍率、备用组、权重、排空 | 当前类型标签不执行入口/出口语义 |
| 转发规则与规则分组 | 新建/编辑/复制、单条和批量启停、目标/端口、归属用户、同步与失败详情、导入导出 | 当前整个领域缺失 |
| 隧道与出口路径 | 入口直出、入口→出口、主备出口、受管隧道及链式路径；显示支持限制 | 当前只有独立协议编译实验 |
| 用户与用户组 | 登录、授权设备组、规则数、到期、禁用、流量额度、速率/IP/连接限制 | 当前只有管理员账号 |
| VLESS 连接 | 在正常开通流程选 VLESS、客户身份、Reality + Vision、安全分发、单链接与撤销；不建立独立订阅业务 | 规则和身份模型已有局部实现，真实多机激活尚未验收 |
| 流量与限额 | 客户/规则用量、倍率、重置策略、重复上报去重、达量/到期停用并确认 | 当前未接计量与限制执行 |
| NY 导入迁移 | 选版本/文件、脱敏预览、关系/冲突校验、未支持项、确认导入与回滚记录 | 当前 CLI 只有结构预检、无真实适配器 |
| 明确排除的商业与推送领域 | 商店、套餐/购买/续费、订单、余额/充值/支付、兑换码、邀请/返利、推送通道/Telegram | 整个领域排除，不保留死菜单、死按钮、字段、权限、指标或存储 |
| 系统运维 | 管理权限、审计查询、安装/升级、公告与设置、备份恢复、通知 | 当前只有部分配置/事件底座 |

## 两种开通流程共用基础

NY 式转发：创建入口/出口组并对接机器（也可直出）→ 建用户/用户组并授权 → 新建规则、选择入口/出口与落地目标 → 分配监听端口 → 下发真实引擎 → 客户连接 → 统计和限制 → 编辑/暂停/恢复。已有机器也可从设备列表加入组；组内对接必须成为直接可用的入口。

VLESS 扩展：在同一流程选 VLESS + Reality + Vision 和直入直出设备组 → 安全签发身份与协议参数 → 下发组内机器 → 返回单一稳定 URI → 网关按新连接调度 → 故障节点摘除 → 客户停用/撤销在全组生效。出口组或 SOCKS5 落地若扩展到 VLESS，须单独验证出站路径，不能由表单标签推断已经支持。

正常开通不要求管理员编写 JSON，不要求再手工编辑网关成员文件，也不让用户从十条 URI 中选择机器。原始配置工具只可放在高级诊断中。是否按每连接轮询与实际请求次数不同；节点故障后的旧连接需要重连，不能承诺无损迁移。

## 实现工作顺序与交付门槛

顺序表示依赖，不缩减完整目标。每个阶段必须有可操作闭环，不以代码包数量、测试数量或页面截图代替功能完成。

| 顺序 | 完整交付范围 | 用户能直接验收的结果 |
| --- | --- | --- |
| 1 | 设备安装/管理 + 入口出口业务模型 + 用户授权 + 结构化转发规则 + 实际引擎适配 | 在隔离机器通过页面开通一条真实传统转发，修改目标生效，暂停断开新连接，恢复可用；重启保留配置 |
| 2 | 用户/用户组、规则分组、端口池、批量操作、计量和基础限制 | 非授权用户不能开通；到期/用尽真实停用，暂停状态保留；端口冲突与失败可定位 |
| 3 | VLESS 身份/安全分发、同流程协议选择、单 URI 签发、控制面→网关成员自动同步、真实 Agent 激活 | 客户只获得一条链接；组成员/权重变化自动生效；停一台测试机器后新连接转到健康成员；撤销凭据后拒绝接入 |
| 4 | NY 原生版本导入器、映射、预检、幂等提交、导入回滚 | 在隔离实例导入脱敏真格式样本，核对用户/组/规则/授权/暂停关系；不写源 NY；未知字段阻断或明确报告 |
| 5 | 隧道高级路径、主备/链式、审计与完整运维、HA | 对照官方和现场功能逐项验收；商业与推送领域按最新范围保持彻底排除 |

数据面路径开发与 UI 同步，避免先画一轮不能生效的页面。关系存储、任务/outbox、凭据和协议健康按这些闭环所需分模块接入；单例 JSON 快照仅作为当前试运行兼容存储，不应成为大规模运营目标。

## NY 语义必须保留

- NY 是 TCP/UDP 转发体系；SOCKS5 经常是落地服务，不能把原始需求理解成“把 SK5 字符串换成 VLESS 字符串”。
- 入口组共享规则与客户端到入口的负载是两个问题；VLESS 新增调度不能破坏现有入口→出口业务组合。
- 官方限制口径与新平台目标分开：NY 速度/IP/连接限制是单入口口径，UDP 不支持这些限制；跨组全局限额需单独实现，禁止显示一个数字却没有执行。
- 规则上下行真实流量与用户按入口/出口倍率扣量分开；不可重复累计两个数据面跳数充当原始规则流量。
- 用户禁用/到期/额度耗尽、规则 paused、规则同步 status 独立建模。现场存在 Normal 且 paused 的规则，导入不能自动启用。
- 一次性注册令牌不等于一键节点安装；保存文件/ACK 不等于引擎运行；端口 TCP 通不等于 VLESS 认证和实际出口可用。
- NY 官方列有 WebSSH；它与当前项目禁止任意远程 shell 的规则冲突。本基线明确保留这一差异，现阶段只设计受限、可审计的安装/诊断/升级操作，不暗中接入任意命令执行。不能因此宣称与 NY 所有运维工具完全相同。
