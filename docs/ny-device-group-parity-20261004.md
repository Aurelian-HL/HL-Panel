## 业务边界

NY 入口组共享转发规则，但设备组本身不负责客户到入口机器的单地址负载。NY TCP、NY UDP、NY SOCKS5 和 VLESS + Reality + Vision 是不同的客户端入口协议。用户要求的一条稳定 VLESS URI 与组内每条新连接的候选调度，是新增稳定接入层的职责，不是 NY 原有设备组设置的直接复制；参考 `docs/ny-official-reference-20261002.md` §3.5。组成员新增、退役及权重更新应投影到网关候选，但现有真实数据面闭环和高可用尚未验收。客户侧不能收到逐节点 URI。

当前本地流程是：管理员选择设备组，发放短期单次注册令牌，Agent 首次注册后自动加入本组。撤销只作用于未使用令牌；已注册节点的认证凭据不能通过“重置组 token”推断为失效。组配置预览仅显示受控字段，不能暴露 Token、节点凭据、私钥或其他秘密。

设备组编辑中的“编辑网络配置”是**放弃当前未保存的组信息修改后进入另一个编辑弹窗**；按钮在组信息有未保存修改时禁用。两类数据分别提交到不同 API，当前不是 NY 截图中的一屏编辑、一次确认或原子保存。

本地 UI 验收使用仓库根目录 `qa-device-groups-api.mjs` 提供仅监听 `127.0.0.1:8080` 的模拟数据，并由 Vite 代理给 `http://127.0.0.1:4177/device-groups`。该夹具不会访问受保护线上服务；浏览器截图、移动视口、控制台和真实后端/节点效果必须分别验收，不能以模拟接口代替。

## 下一步验收

1. 发布带签名/校验的 Agent 在线与离线安装器，提供实际可复制且经过隔离环境验证的自动探测与海外主线路命令。
2. 建立管理员可见的节点期望配置查询和 applied generation 对照，并对输出做秘密字段过滤。
3. 明确 NY UDP 智能绑定的协议与数据面语义，再决定是否引入字段。
4. 在隔离测试环境验证单一稳定入口的 VLESS 新连接调度、故障摘除与恢复，最后用真实客户端验收；不得用控制面保存成功代替流量验证。
