# 间歇性超时维护计划

本文记录 HL-Panel 客户出现“刚开始正常、运行一段时间后间歇超时、随后恢复”的排查链路和维护要求。它是源码和线上观测的操作清单，不把本地测试结果当作线上结论。

## 排查链路

1. 客户端到订阅地址和入口 HTTPS：检查证书链、SNI、响应时间、连接重置和订阅响应大小。
2. 网关 membership 快照：确认组内成员地址、权重、draining/offline 状态和协议健康租约来自同一份已提交快照。
3. 节点 heartbeat：检查最近心跳时间、启动实例、已应用配置代数、应用结果和资源采样是否连续。
4. desired 配置应用：检查 watch/poll 请求、配置代数、配置摘要、应用回执和失败重试，确认旧配置仍被保留。
5. protocol probe：检查挑战耗时、失败原因、租约续期和发布延迟；数据库发布变慢不能阻塞探测调度。
6. 网关拨号：检查后端拨号失败、节点临时摘除、重试预算、连接关闭和恢复后的重新加入。
7. PostgreSQL：检查快照行锁等待、事务耗时、连接池耗尽、慢查询和死锁；重点关注高频 heartbeat 与协议健康发布的竞争。

## 本地代码防护

- 协议健康发布使用有界异步发布队列。数据库短暂阻塞时，探测、租约续期和故障摘除继续运行；失败批次保留并指数重试，队列有上限避免内存无限增长。
- heartbeat 的资源采样按 30 秒持久化一次；启动实例、应用代数、引擎版本、能力和应用状态变化立即持久化。读取仍返回当前请求中的采样，重启恢复使用最近一次已持久化快照。
- 网关后端拨号失败会在预算内切换候选，并临时摘除失败成员；拨号成功仅清除短暂的拨号冷却。主动探测否决独立保留，只有连续成功探测达到恢复阈值才解除，不因并发拨号成功、冷却到期或租约续期提前解除。
- 采集流量窗口与提交引擎配置共用生命周期锁，避免旧进程流量误记到新代数；慢网络投递留在锁外，避免控制面故障阻塞本地恢复。
- 更新完整节点配置时，未变化引擎保留已有进程和计数代数；需同时核对验证后的原生配置、磁盘文件与受管存活进程摘要。相同文件不能证明进程仍运行，无效回滚不能先停止健康进程。
- 双引擎局部退出后的恢复，在准备或校验阶段失败时保留仍存活的另一引擎，避免尚未提交配置就清空全部进程；提交或验证阶段失败仍执行安全清理，并保留持久化的最后有效配置供后续重试。此防护不能替代共享引擎配置真正变化时的无损热更新。
- Xray/GOST 原生配置校验各自最多运行 15 秒，并遵守父上下文更短的期限。到期终止校验子进程、回收进程并返回脱敏的校验失败，释放生命周期锁；该期限不会限制正常转发进程的寿命。控制面长期上下文不能替代校验进程的独立期限。

上述防护已纳入 v0.1.82 正式版本。面板和节点分别升级后，才能依据实际运行版本判断对应防护是否生效；只更新面板不代表节点已具备这些行为。代码发布也不代表客户原网络的长期超时已经消失。

## 同订阅、不同网络的分段排查

同一份订阅只保证客户端获得相同入口和协议参数，不保证解析到同一 IP，也不保证使用相同运营商路径、DNS 缓存或出口。维护者可用而客户超时时，需要保留客户原网络和失败时间，再对照：

部分客户切换手机热点恢复、部分仍失败时，不得统一归因为客户端或运营商。切换网络同时可能触发重新解析、重建连接和重新选择入口。应在同一时间窗口交错采样故障规则和对照规则，并分别检查节点到客户出口的完整请求及 Reality 握手目标；不同时段的成功只能证明该时段可用。

| 分段 | 必须验证 | 不能据此推断 |
| --- | --- | --- |
| 订阅下载 | HTTPS 证书链、客户端时间、响应码和实际内容 | 已导入节点的转发一定可用 |
| 客户到入口 | 实际解析 A/AAAA、选中地址、真实 VLESS/Reality 握手和目标请求 | 服务器本机测试成功代表客户运营商路径正常 |
| 入口配置 | 每个解析地址的有效客户身份、Reality 参数、端口、应用代数和进程 | 心跳在线或历史应用成功代表客户请求正在成功 |
| 入口到出口 | 使用当前客户规则的出口认证、目标 CONNECT、TLS 和响应 | TCP 端口开放代表 SOCKS5 认证和出口可用 |
| 持续连接 | 在同一时间窗口观察退出、重传、资源、出口拒绝和配置切换 | 一次 204 响应代表长期故障已消失 |

专用入口协议 probe 可以被路由到节点本机 echo，绕开客户出口，因此其租约不能作为客户完整线路健康证明。DIRECT 设备组路由与 VLESS 的 SOCKS5 landing 是不同维度，不要只凭字段名称判断配置冲突。

多个 A 记录直接指向节点时，客户连接绕过 `connection-gateway`。网关摘除不会改变公共 DNS、客户端缓存或已有 TCP 会话。不得通过盲目重装、轮流替换地址、关闭 TLS 校验来掩盖尚未定位的故障。

现场仅做有界的只读诊断，不记录客户 IP、凭据、订阅令牌或连接内容。更改 DNS、隔离成员、重启引擎等可能影响现有连接的操作，需要明确操作范围、备份与授权。

## 发布回归

### Reality / Vision 内核与目标

当前固定 Xray `26.7.28` 恢复旧 Chrome/Safari Reality 握手兼容性，但仍存在上游 [#6834](https://github.com/XTLS/Xray-core/pull/6834) 描述的 Vision TLS 收尾缺陷。`26.10.10` 包含收尾修复，却无法兼容部分旧指纹；不能用全量升级替代兼容性验收。完整依据和限制见 [内核兼容性维护](../xray-compatibility.md)。客户端真机与长期运行仍需持续检查。

心跳上报 Agent 初始化时读取的真实安装内核版本；读取缓存不启动新进程。需同时核对进程运行状态、配置应用结果和实际转发，版本字段本身不证明连接健康。替换二进制后应通过正式节点升级流程重启 Agent，让缓存和受管引擎一致。

规则编辑器支持独立的 Target / SNI，自定义目标也自动生成密钥；复制保留目标并生成独立密钥。编辑保留已签发密钥，不批量替换旧规则目标。改变 SNI 后应通知客户更新订阅。目标验证失败需区分 DNS、TCP、TLS 1.3、X25519、证书和 SNI，不用端口开放替代 TLS 验证。

`tests/integration/xray/live_remove_test.go` 确认 `rmi` 虽能保留无关连接，但被移除监听器的旧会话也可能继续传输。因此当前不能把暂停、额度耗尽、权限撤销统一改为删除 API；这些变更仍需要完整应用，存在一次节点连接中断。发布说明必须保留这一限制。

### 独立新增 Xray 规则

旧实现即使只新增一条规则，也会停止共享 Xray 进程，导致其他规则上的已有连接中断。参考面板使用本机 HandlerService 添加监听；这项实现差异可在隔离环境复现，不能直接当作客户每次间歇超时的唯一原因。

独立新增规则支持本机 API 应用：先添加出口和完整路由，再开放新增监听，保留原进程与流量计数代数。新增内容失败时撤销本次监听和出口、恢复原路由；请求超时造成执行结果不确定、补偿失败或进程退出时，重建最后有效配置。API 仅限受管的 loopback 地址，配置通过标准输入传递，诊断不输出配置或认证。

适用条件包括原有入口、出口及全局设置不变，默认出口不变，原路由顺序不变，新增路由只匹配新增入口。编辑、删除、默认出口变化或旧版进程未开启所需 API 时，仍采用完整配置应用并中断该进程的连接。规则排序可能改变默认出口，因此不能宣称所有新增规则均不重启。

节点升级后才具备此行为；升级本身需要一次进程启动。更新应逐台进行并保留配置、身份和账本备份。正常补偿不能证明不确定的迟到 RPC 已结束，必须恢复最后有效进程，不能为保留连接放弃一致性。

验收需保留同一条真实 TCP 连接，连续新增、回滚、制造隔离监听冲突再重试，同时核对进程 PID、计数代数、监听清理与磁盘配置。只有重新拨号成功不足以证明旧连接被保留。

以下用例必须保留在仓库，修改相关模块后重跑：

- `internal/routing/endpointrouter/probe_veto_test.go`：主动探测否决不被拨号成功、冷却到期或续租绕过；地址变化和旧 revision 分别处理。
- `internal/gateway/healthprobe/controller_test.go`：只有达到恢复成功阈值才解除主动否决。
- `internal/agent/runtime/usage_delivery_test.go`：流量采集不能跨配置提交；慢网络投递不阻塞配置和本地恢复。
- `internal/agent/engine/unchanged_process_test.go`：未变引擎不重启，退出进程可恢复，篡改或无效回滚不会误保留或终止健康进程。
- `internal/agent/engine/xray_live_add_test.go`：严格拒绝影响已有流量的变更；验证增量添加、部分失败补偿、事务回滚和不确定 RPC 的最后有效配置恢复。
- `tests/integration/xray/live_add_test.go`：真实 Xray 对照旧实现的断流，验证同一 TCP 连接在连续新增、回滚和部分监听冲突补偿后仍可用。全部故障注入限定 loopback，不代替客户原网络上的 VLESS/Reality 验收。
- `internal/agent/reconciler/recovery_failure_test.go`：启动恢复、后台恢复和同代数恢复的准备/校验失败不停止健康组件；提交/验证失败仍清理未验证进程，保留最后有效配置并支持重试。
- `internal/agent/engine/validation_process_test.go`：用隔离子进程复现校验挂住，确认内部截止期限、父期限、提前取消以及诊断脱敏，不连接生产服务。
- `tests/integration/gost/mixed_stability_test.go`：固定版本真实 Xray/GOST，保留同一 TCP 会话连续更新并回滚另一引擎。用例是 loopback TCP 转发，不代替完整 VLESS/Reality 路径。

面板与节点分别更新，main 提交不等于运行版本升级。发布使用不可变标签和正式流水线；真实数据库测试未配置时必须标记跳过，不得计为数据库验收通过。

## 节点升级检查

1. 先清点所有在组内且在用的节点，核对面板运行版本与每台节点的 `agent_version`；只升级面板不会更新节点程序。
2. 使用 README 的**节点机更新**命令逐台升级，无需重新生成注册令牌。旧安装缺少本地升级器时使用仓库正式标签的 `update-node.sh`，不要重新注册覆盖身份。
3. 核对更新前后的身份、注册凭据摘要、配置摘要、流量账本备份和回滚脚本。客户同期编辑规则可能使应用代数变化，需要与业务审计时间对照，不能直接当作升级丢失配置。
4. 等待每台节点的新版本心跳和 `desired_generation == applied_generation`，核对应用成功、原生引擎进程和监听。协议健康必须按服务端的部署匹配与观测替换规则合并快照和实时 overlay，再判断租约、代数及地址；仅统计其中一张表会漏掉观测，旧快照也不能单独证明当前健康。
5. 记录升级引起的正常重启和业务配置更新的重启。升级会短暂中断该节点的现有连接；逐台执行并保留备份。若客户端通过多 A 记录直连节点，逐台更新也不能保证客户端自动选择其他节点。
6. 在没有配置变化的窗口持续对照进程 PID、重启次数、文件描述符、内存、心跳、租约和错误增量。不要通过循环重启来隐藏异常，也不要以单次正常证明长期稳定。

## 指标和日志

每次发布前后应记录并观察：

- heartbeat 请求数量、延迟、失败率和最近持久化时间；
- desired-watch/轮询延迟、超时、应用代数和回执失败原因；
- protocol probe 持续时间、失败原因、租约剩余时间和发布队列积压；
- PostgreSQL snapshot 事务等待、事务持续时间、连接池使用率和锁等待；
- 网关 backend dial 失败率、候选切换次数、临时摘除次数和恢复次数；
- 订阅请求的状态码、响应耗时、连接重置和 TLS 错误。

## 维护周期

- 每次版本发布：在 loopback 隔离环境执行 `go test ./...`、`go test -race ./...`、`go vet ./...` 和 `git diff --check`。
- 每周：检查上述错误率、数据库锁等待、协议租约过期和订阅下载失败，按规则/组/节点维度聚合。
- 节点扩容或规则数量明显增加：重新评估探测 worker、发布队列、数据库连接池和快照大小，禁止只提高并发而不观察资源。
- 每月：演练单节点拨号失败、节点恢复、控制面短暂不可达和快照恢复，确认客户使用旧配置不会中断。

### 发布后连续观察

先完成约 5 分钟短窗口，再观察至少 2 小时，覆盖客户反馈的运行一两个小时后异常。记录观察起止时间、采样间隔和采样失败数；已启动观察不能写成观察完成。

- 固定配置代数时，对照代理与引擎 PID、服务重启次数、RSS 和文件描述符；有业务配置变化时，先区分正常应用造成的进程变化。
- 将内存、文件描述符变化与连接负载一起判断。短时间上涨不能单独证明泄漏，短时间平稳也不能排除长期泄漏。
- 分别记录心跳、协议健康租约、配置匹配和数据库锁等待。心跳在线或探测正常不能替代客户原网络上的真实请求。
- 观察程序只读采样，限定运行时长、CPU 和内存，不更改节点服务、不循环重启。记录聚合错误分类，避免保留客户对端、连接内容或凭据。
- 观察结束后汇总结果并安排复查。SSH 会话失效、采样失败、日志窗口截断或机器重启导致临时记录丢失时，应写明证据缺口，不得按“无错误”统计。

## 回滚和线上验证

本地修改保持在独立工作树，回滚使用对应提交的 `git revert <commit>`，不得用 `reset --hard` 覆盖其他未提交工作。线上仍需在授权的隔离环境验证：数据库锁等待下降、采样不再过期、协议租约能够持续续期、单节点故障可切换且订阅客户端可重新连接。本文件不代表客户线上问题已经解决。
